然后手工把 `docs/协作/AGENDA.md` 加一行，保证最多一行"进行中"。

**④ 只做计划（复杂任务开工前）**
```text
先不要改代码，先给计划并回答四件事：改哪里（文件路径列全）· 复用什么（已有类/配置）· 影响哪些功能（接口/DB/配置）·
怎么验证（命令+期望+exit code）。另外声明本次不动的范围；要碰公共组件先说明原因+影响，等我确认。
```

**⑤ 独立审查（不同上下文，只读）**
```text
你是独立代码审查者，不参与实现。除 docs/协作/review/ 下的报告外只读。
输入：git -C D:\new\projects\meeting-notes diff origin/main...main
依据：docs/项目/录音纪要平台/spec.md 的 DoD
要求：只报有证据的问题（文件:行号+复现命令+影响）；分阻塞/建议；报告写到 docs/协作/review/<日期>-reviewer.md；
      结尾按"测试三问"写：检查了哪些场景 / 实际运行了哪些测试 / 还有哪些没验证（不许留空）。
```

**⑥ 独立验证 / 红队**
```text
你是独立验证者，不信任任何"测试已通过"的口头结论：
1) 干净状态复跑（命令+exit code+关键输出）；2) 查测试有没有被削弱（被删的 assert / 新增 skip / 关键对象被 mock）；
3) 用真实规模数据跑一次；4) 输出证据 → 通过/不通过 → 该补哪个测试。
（红队版：只针对本次 diff，构造 10 个恶意/边界输入，每个给 输入/期望/实际/复现命令，不许改业务代码。）
```
