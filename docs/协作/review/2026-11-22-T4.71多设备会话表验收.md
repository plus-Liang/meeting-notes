## 6. 建议（不阻塞）

- **S1（文档一致性，建议随下一张卡修）**：两处注释仍描述旧语义——
  `ApiTokenFilter.java:25`「否则按**账号令牌**处理：SHA-256 hex 查 `{@code app_user.token_hash}` → 该用户 id」（实际查 `user_session`；同类描述另见 `:110` 的方法注释）；
  `TokenService.java:13-14`「同一用户仅保留一个有效令牌，重新登录即轮换（旧令牌立即失效——`token_hash` 被覆盖）」——T4.71 后这两句都不成立。**注意**：本项目曾因这类「代码已改、注释没改」开过 T4.63 的卡（K-126/K-127），故此处必须留痕。
- **S2（语义）**：迁移行 `created_at` 取的是迁移时刻（`DEFAULT now()`），不是真实签发时间。若升级后立刻连登到上限，被淘汰的会先轮到迁移来的会话（它也是最老的，结果无损），但 `sessions` 列表里迁移行的「创建时间」会显示成升级时刻。建议在迁移 SQL 注释里写清这一取舍。
- **S3（性能）**：`ApiTokenFilter.java:137` 每次带令牌的请求都 `UPDATE user_session SET last_used_at = now()`——写放大到「每请求一次写」。自托管规模可接受，若要省可改为「与上次记录相差 > 60s 才更新」。写码方未声明此项。
- **S4（功能面）**：`/auth/sessions` 无分页（会话数受 `max-sessions` ≤10 封顶，当前无必要）；前端暂无会话列表 UI，属 O-2 的另一半，可另立卡。
