**F-1（必修，P1）：DONE 写在了摘要之前，"DONE = 结果就绪"不成立。**
日志时间线（task 73，同一进程）：
```
14:42:28.568  转写结果已落库（transcript 512 字）   ← 此处已置 DONE
14:42:31.880  摘要已落库（170 字，8 个关键词）      ← 3.3 秒后才写摘要
```
我的轮询实际撞到：`status=DONE` 时 `summary=null`、`ai_tier=null`，几秒后才出现。
这与 D-068 选"同步做"的理由（DONE 即全部就绪、外部消费者不用二次确认）**直接冲突**；Webhook/接入方按 DONE 回调就会读到半成品。
**修法**：把置 DONE 挪到摘要之后（先写 transcript → 摘要 try/catch → **最后**置 DONE；摘要失败也照样 DONE），约 10 行内。

（给工厂包私有标识或直接 `assertSame` 到字段）。

**F-3（P3，记着不改）**：`TaskController` 在 row mapper 里 `new ObjectMapper()`（每行一次）、`SummaryService` 也自建 ObjectMapper；
不影响正确性，后续注入单例即可。
