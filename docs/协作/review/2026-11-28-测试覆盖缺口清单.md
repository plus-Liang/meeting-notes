## 3. 结论：真正没测过的是什么

### P0（不补测就不能对外说"可用"）

1. **真人验证（DoD 第 11 条）**：V-01/V-02/V-03/V-04 + F-01/F-02/F-03/F-04/F-05 的真人版本。当前所有"价值"数字都是 AI 估算，没有一条来自真人。
2. **冷启动公网路径**：干净机器 `git clone`（公网）→ `first-run` → **461MB 模型首次下载**。sim3 的「4 分 00 秒」是本地仓 + 缓存模型，**不是陌生人会遇到的路径**，这是最大未知项。
3. **回滚演练**：升级失败后的退路（上一版镜像 + DB 快照）。V16 迁移不可逆，现在没有任何回滚证据。

### P1（上线后必然遇到，缺证据就靠运气）

4. 移动端（iOS Safari / Android Chrome）核心链路 —— 手机是第一入口。
5. Firefox/Safari 桌面兼容（剪贴板、`<details>`、录音编码）。
6. 双用户越权对抗（A 打 B 的 id：GET/PATCH/DELETE/export/audio/share）。
7. 同任务并发操作（A 删除时 B 在编辑/观看）与成员配额独立。
8. 客户端上传中断/重连、批量 20 文件、>60 分钟音频。
9. 反向代理 + HTTPS + 限流按 IP 聚合（K-176）。
10. 跨天配额重置（真实 23:59→00:01）。
11. 日志轮转/容量上限（当前 compose 无 `logging` 段）。
12. 真实告警链路（Prometheus 规则→通知）。
13. 在线备份一致性（备份期间有写入）。

### P2（可排队，影响面小）

14. 可访问性（键盘全流程、读屏、对比度、200% 缩放）。
15. 跨时区部署（`TZ=UTC`）下配额日切与回收站天数。
16. 文件名编码（GBK/emoji/超长名）。
17. 万级任务下的列表/搜索性能；2 万对象截断下的存储统计。
18. 畸形 JSON / 超长 header / zip bomb 的 400 契约。
19. 分享 token 枚举限流。
20. webhook 重复投递修复（已知 17ms 重复，D-235 S1）。
21. 台账行内直接打标签（体验缺口）。

## 4. 能否据此判定"可以发版"

**分两层说，别混。**

| 判断 | 结论 | 依据 |
|---|---|---|
| **能不能继续发布/交付（工程维度）** | **能**。可以继续按 `v0.1.x` 打 tag、自托管部署给愿意折腾的人 | 142 份验收报告、780 条单测、CI #190 + smoke #163 双绿、主栈 5/5、备份恢复/升级/自愈/优雅停机/限流/配额/回收站均有真栈证据 |
| **能不能宣称"陌生人 30 分钟自己跑通"** | **不能**。目前没有一条真人证据，冷启动公网路径也没跑过 | DoD 第 11 条未完成；sim3 的冷启动是本地仓 + 缓存模型 |
| **能不能宣称"生产级"** | **暂不能**。缺回滚、告警链路、移动端、越权对抗四类证据 | 本清单 P0-3 与 P1-4~12 |

一句话：**工程上可发，产品上未验证；对外话术必须是"可自托管的 beta"，不是"已验证生产可用"。**

## 5. 最该补的三项（按性价比排序）

1. **真人 3 人**（材料已就绪：`01-上手卡`、`02-反馈表`、`06-清单`）——一次投入同时补上 P0-1 与全部 V-xx、F-0x 真人版本，是唯一无法用自动化替代的。

3. **回滚演练**（上一版镜像 + DB 快照）——成本半天，但直接决定"出事时有没有退路"。
