## 2. 任务 B（T4.18）：三系统冒烟 —— 结论：**初版即红，修复后转绿**

### 2.1 第一轮：真 CI 直接红（这是本轮最重要的收获）

- push `415a794` → run **44886492108**（workflow `first-run-smoke`）：`ubuntu-latest` success、`macos-latest` success、**`windows-latest` failure**
- 失败在「PS 5.1 语法 + UTF-8 BOM 校验（Windows）」，job 日志：`+ ... throw ("ç¼º UTF-8 BOMï¼ˆ...)` → `ParserError … UnexpectedToken` → `exit code 1`
- **根因**：GitHub Actions 把 `run:` 块落成**无 BOM 的 UTF-8 临时 `.ps1`** 再交给 `shell: powershell`（PS 5.1）；PS 5.1 对无 BOM 文件按 ANSI 解码 → 内联脚本里的**中文注释/中文 throw 消息**变乱码 → **解析阶段**就炸。`chcp 65001` 与 `$OutputEncoding` 都无效（解析先于执行）。
- **讽刺点（写进坑库）**：这个 workflow 的职责是「检查所有 `.ps1` 必须有 BOM」，而它自己的内联脚本因为拿不到 BOM 而死。K-101 系列第三次出现，前两次是"脚本文件本身"，这次是"脚本片段被宿主落盘后失去 BOM"的变体。
- 同 commit 的 `ci.yml` run **44886492129** = **success**（产品无回归，红的是新增的旁路 workflow）。

### 2.2 修复（`4363fb3`，方案 A：内联脚本改纯 ASCII）

- diff：`1 file changed, 6 insertions(+), 6 deletions(-)`，只动 `first-run-smoke.yml`；`ci.yml` 不在 diff；未新增 `scripts/check-ps1.ps1`（方案 B 未采用，理由：临时文件补 BOM 不可控于 GitHub 落盘行为）
