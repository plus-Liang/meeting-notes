## 六、建议（均为提示级，不阻塞）

- **S1（实测放大风险，值得排期）**：redis 断开时 `/actuator/health` 阻塞 **60.04s**（Lettuce 默认 command timeout 60s，`application.yml` 未显式设置 `spring.data.redis.timeout`）。改造后容器 healthcheck `timeout: 3s` + `retries` 会在这 60s 内先判 unhealthy，容器可能被重启（若将来加自动重建），且 readiness 探针同样慢。建议后续把 health 依赖项超时显式下调（如 `spring.data.redis.timeout: 3s`），并让 readiness 组不包含慢依赖。
- **S2（可维护性）**：`ApiTokenFilter` 现在把 `/api/v1` 与 `/actuator` 两个前缀硬编码在同一个布尔表达式里；将来加 `/api/v2`、`/management` 之类前缀容易漏。建议抽成 `List<String> protectedPrefixes` 常量或配置项，并在注释里写「新增受保护前缀必须在此登记」。
- **S3（破坏性变更的落地位置）**：本轮变更对升级者是真破坏（Prometheus 抓取、任何匿名健康探针、旧镜像 healthcheck 都会 401）。目前只写在验收报告与交付回报里，建议在 `运维-监控与告警.md` 顶部加一条「**升级注意**：0.1.x 起 `/actuator/**` 需 Bearer，抓取配置必须同步改」，并在 README 的版本说明里点一句。
- **S4（体验细节）**：`settings.html` 的 health 请求走 `apiFetch`，凭据失效时会 401 → 清登录态并跳登录页。行为本身正确，但「看系统状态」导致被登出略突兀。可后续对 actuator 请求做单点降级（显示「未知」而非强制登出）。
- **S5（测试资产）**：`NoKeyStartupTest` 里「401 body 不含 `components`」是很好的**泄漏面断言**，建议固化为公用断言工具，给其它 401 路径也复用，防止将来某个错误响应体把内部字段带出去。
