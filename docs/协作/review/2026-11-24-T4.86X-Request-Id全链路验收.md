## 五、建议（均不阻塞）

- **S1（建议）**：`X-Request-Id` 回显值允许 `.`/`-`，建议在 `接入指南.md` 注明「网关请原样透传，不要改写」——否则反代自己生成的不合规头会被服务端替换，上游追踪链断在网关。
- **S2（提示）**：卡面白名单未含「连带测试」，导致写码方必须超白名单 5 文件 + 一次 amend。下次同类卡面应把 `app/src/test/java/com/meetingnotes/**` 一并列入白名单（本次已核：只加 matcher、断言零改动，可接受）。
- **S3（提示）**：worker 先 `open(taskId, null)` 再覆盖写 requestId，正确性依赖 `open` 幂等覆盖。若将来有人把 `open` 改成「已有键不覆盖」，requestId 会静默丢失且测试未必红——建议在 `TaskLogContext` 类注释里写明「open 必须覆盖」。
- **S4（提示）**：`RequestIdFilter` 未对静态资源特判（卡面要求如此），静态页请求也走一遍 MDC，成本可忽略但会让访问日志的 requestId 数量虚高，排障时注意按 logger 过滤。
- **S5（提示）**：`V12` 迁移可空无索引是对的，但**历史 179 条任务 `request_id` 全 NULL**，`task-<id>` 回退会让这些任务在 webhook 侧看起来像「有 id」——文档已写「老办法用 taskId」，可接受。
