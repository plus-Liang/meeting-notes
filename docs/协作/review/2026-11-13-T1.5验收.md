## 2. 对作者 4 条质疑的裁决（全部采纳，但性质不同）

### 质疑 1：Spring AI 内部重试架空 RETRYING 状态机 → **采纳，D-046**
- 我做的机制核对：解压 `spring-ai-openai-1.1.8.jar` 逐 class 扫描 → `OpenAiAudioTranscriptionModel.class`
  **确实包含** `DEFAULT_RETRY_TEMPLATE` 引用；`spring-ai-autoconfigure-retry` 的
  `spring-configuration-metadata.json` 里 `spring.ai.retry.max-attempts` / `backoff.*` **真实存在**（1.1.8）。
  → 说明"收敛内部重试"的机制成立，不是巧合。
- 效果核对：我实测失败路径 **9s** 走完 3 次尝试（作者报 11s，同一量级）。
- 落地：`AI_RETRY_MAX_ATTEMPTS=2` / `AI_RETRY_BACKOFF_INITIAL_MS=2000` / `AI_RETRY_BACKOFF_MAX_MS=10000` 已进 yml + `.env.example`；
  `error_code` 只放稳定码（列宽 64），完整原因进 `dead_letter.reason`（TEXT）——这同时修掉了"二次故障把任务卡 RUNNING"的真 bug。

### 质疑 2：404 错误码不在 D-041 的 6 个里 → **采纳，D-047**
码表扩为 **7 个**（只增不改），`接入指南.md` §3.3 已加 `404 TASK_NOT_FOUND` 行 + "码表只增不改"说明。

### 质疑 3：无语音文件被判 DEAD → **改语义，D-048（T1.6 前置实现）**
`200 + 空文本` 是**业务结果**不是故障：改判 `DONE` + `transcript=""`，前端提示「未识别到语音内容」，不重试、不写 dead_letter。
理由与已排除项（新增 EMPTY 状态 / 只重试一次）见 D-048。

### 质疑 4：DEAD 任务幂等重传原样返回 DEAD → **采纳为 T2.1 设计约束，D-049**
T1.5 不改（卡片明确把幂等恢复划给 T2.1，扩范围要先确认）；已写进 `接入指南.md` §3.3 "已知限制"，

## 3. 建议项（不阻塞，已分配）

### S-1 273 行新 worker 零单测（M-8 边缘）
- 事实：`TranscriptionWorker` 是当前最复杂的类（状态机 3 条分支 + 文件生命周期 + 外部进程），`app/src/test` 里没有它的测试。
- 影响：改 D-048 时没有回归网；下次重构（T2.x 并发 / T2.3 崩溃恢复）只能靠真机试。
- 改法：T1.6 的 D-048 改动**必须**带 1 条单测（空文本 → DONE + 空串）；状态机三分支的集成测试排进 T1.8 或 T2.x 卡片。

### S-2 `mvn test` 的绿依赖两个环境前提，干净 clone 会红
- 事实：不设 `ASR_BASE_URL` 时 `AsrSmokeTest` 报 `ResourceAccessException: http://asr:8000`，**14 用例里 1 error**
  （我第一遍就是这样，补 `ASR_BASE_URL=http://localhost:8001` 后 14/14）；`.env` 也不能进版本库。
- 影响：换机器/换 agent 时"我这边绿"不可复现；已在 T3.3 登记为"干净 clone `mvn test` 红"。
- 改法：T3.3 提供 `scripts/test.ps1`（注入 `.env` + 覆盖 `ASR_BASE_URL` + 一句 exit code），把它变成**唯一**测试入口。

### S-3 `GET /tasks/{id}` 不返回 `error_code`，但详情页要显示 DEAD 原因
- 事实：`TaskStatusResponse` 只有 `id/status/duration_sec/size_bytes/created_at/transcript`；
  T1.6 详情页要显示失败原因（`error_code`）却拿不到。
- 改法：在 T1.6 卡里**显式允许**给该响应追加 `error_code`（nullable，只增不改，D-041 允许），并同步 `接入指南.md` 一行。
