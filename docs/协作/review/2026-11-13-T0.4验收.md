## 1. 关于 `base-url` 偏差：判定"接受"，工作方式对、我此前的指令错

**它的说法**：Spring AI 1.x 自己追加 `/v1/audio/transcriptions`，所以配置值不能带 `/v1`。

**我独立验证**（反编译本机 m2 里的 jar，不是听它说）：

```powershell
javap -p -c -constants -cp spring-ai-openai-1.1.8.jar org.springframework.ai.openai.api.OpenAiAudioApi
# 输出包含：
#   143: ldc  #222  // String /v1/audio/transcriptions
#   9:   ldc  #75   // String /v1/audio/speech
```

→ **确认**：`OpenAiAudioApi` 内部硬编码 `/v1/audio/transcriptions`。若 `base-url` 写成 `http://asr:8000/v1`，
实际请求会变成 `/v1/v1/audio/transcriptions` → 404。

**判定**：
- **契约端点不变**：仍是 `http://asr:8000/v1/audio/transcriptions`（ASR 服务侧不用改）；
- **配置值改为** `ASR_BASE_URL=http://asr:8000`（不带 `/v1`）；
- 它提的两个替代方案（ASR 加 `/v1/v1` 别名路由 / 升 Spring AI 2.0.x）**都不采纳**：前者脏、后者要求 Spring Boot 4 违反技术栈。

→ 已记入 `决策记录.md` **D-034**，并同步到全部文档（此前 6 处文档写的是带 `/v1`，是我的错）。
