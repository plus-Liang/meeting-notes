# T4.15 缺陷验收报告（第 81 份）：完整模型被误判「未下载完」，`-Force` 还会把它删掉

- **报告日期**：2026-11-21
- **验收人**：Lead（独立上下文，非写码方）
- **被测对象**：`D:\new\projects\meeting-notes` HEAD `53931a9` 的 `scripts\download-model.ps1`（99 行）与 `scripts\first-run.ps1`（92 行）——T4.14b 引入的完整性校验
- **结论**：**发现缺陷**（P1，写码方不再算通过）。T4.14b 修的 F1 是「假完成」，本次是**反向回归**：461MB **真下载完整**却被判「不完整」，`exit 1`；`first-run.ps1` 因此中止；用户照提示加 `-Force`，脚本会把已下好的 463.7MB 缓存**整目录删除**。
- **证据目录**：`D:\new\artifacts\T4.15-download\`
- **修卡**：`D:\new\artifacts\T4.15-download\card-T4.15-fix.md`（已可直接粘给写码方）

## 0. 触发方式（真实路径，不是夹具）

用 T4.14b 修好后的脚本做一次**真实的 461MB 下载**（D-167 §6 遗留的「干净网络完整下载」）：

```powershell
cd D:\new\projects\meeting-notes
$env:HF_ENDPOINT='https://hf-mirror.com'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\download-model.ps1 *> D:\new\artifacts\T4.15-download\dl-attempt3.log
```

## 1. 现象：下载 100% 成功，脚本仍报「不完整」

`dl-attempt3.log` 关键行（原文）：

```
Fetching 6 files:  50%|█████     | 3/6 [00:09<00:00,  3.73s/it]Error while downloading from https://hf-mirror.com/Systran/faster-whisper-small/resolve/536b0662742c02347bc0e980a01041f333bce120/model.bin: [SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol (_ssl.c:1010)
Trying to resume download...
Fetching 6 files: 100%|██████████| 6/6 [10:15<00:00, 102.53s/it]
[download-model] 下载流程已结束但模型仍不完整（缺 model.bin、config.json、tokenizer.json、vocabulary.txt）。建议清除后整包重下：
  powershell -NoProfile -ExecutionPolicy Bypass -File scripts\download-model.ps1 -Model small -Force
```

`exit code = 1`。中途 1 次 SSL 断连由断点续传自动补上，**最终 6/6 文件全部取到**。

## 2. 证据链：模型其实是完整可用的

| # | 检查 | 结果 |
|---|---|---|
| 1 | `models` 体积 | **21 文件 / 463.7 MB**；`blobs\3e3059215…d671`（model.bin 的 blob）= **483,546,902 B** 真文件；其余 blob 2,203,239 / 459,861 / 2,370 / 1,998 / 1,477 B |
| 2 | 容器内视角（Linux） | `ls -l snapshots/536b…/` 全是 `lrwxrwxrwx … -> ../../blobs/<sha>`；`stat -L model.bin` = **483546902** |
| 3 | Windows 侧视角（PS 5.1） | `exists=True Length=0 Reparse=True Attributes=Archive, ReparsePoint`，`LinkType`/`Target` 均为空 |
| 4 | 能否真的推理 | 用该缓存起 `meeting-notes-asr:latest`：`/health` = `{"status":"ok","model":"small","ready":true}`，启动加载 4.3s；8 分钟音频转写 **21s**，返回 1093 字符 |
| 5 | 与主栈（`D:/huggingface`）比对同一音频 | 两次转写文本 **完全一致**（各 162 字符，`$j1.text -eq $j2.text` = True） |

**根因**：下载在 **Linux 容器内**执行（`snapshot_download(..., cache_dir='/dl/hub')`），HuggingFace 在 `snapshots/<rev>/` 下建的是**符号链接**。Windows 读不到 WSL 符号链接的目标 → `Length` 恒为 0。T4.14b 的判据 `$item.Length -le 0 → 缺失`（`download-model.ps1:31-34`、`first-run.ps1:23-39` 内联同款）因此把**完整**缓存判成不完整。

## 3. 后果：不是「多问一句」，是「删掉再重下」

`first-run.ps1` 面对这条完整缓存（`D:\new\artifacts\T4.15-download\firstrun-symlink.log`，`exit 1`）：

```
[first-run] 检测到 faster-whisper-small 下载不完整（缺 model.bin、config.json、tokenizer.json、vocabulary.txt），重新下载…
[download-model] -Force：清除 D:\new\projects\meeting-notes\models\hub\models--Systran--faster-whisper-small 后重新下载…
[download-model] 开始下载 faster-whisper-small …
[download-model] 使用镜像源：http://127.0.0.1:9
[download-model] 下载失败（exit 1）。…
[first-run] 模型下载失败，中止。
```

事后实测：该目录下 **463.7MB 缓存已被删除**（只剩 7 个 0 字节日志锁文件）。
在弱网环境（本次下载中就出现过 SSL 断连）会形成死循环：**下满 → 判不完整 → 删掉 → 再下满**，用户的 461MB 永远用不上。这是本报告的 P1 依据。

> 测试安全说明：这一条是在**受控夹具**里复现的——先把仓库 `models` 改名 `models.real`，再用 `mklink /J models models.real` 指回去（T4.14b-fix 刚修好「junction 只删链接」），因此 `-Force` 的破坏路径与真实用户一致；主栈模型 `D:\huggingface\…\model.bin` 全程仍为 483,546,902 B 未受影响。

## 4. 附带确认（本次顺带验证的两件事）

| 检查 | 结果 |
|---|---|
| 目录内含 **WSL 符号链接**时 `Remove-Item -Recurse -Force` 会不会炸（K-101 的延伸） | **不会**。容器造 `d/{real.txt(6B), link.txt→real.txt}`，PS 5.1 `Remove-Item $d -Recurse -Force` → `删除成功，仍存在=False`，无异常 |
| 修卡要求的「条目带 ReparsePoint 即视为已下载」是否够用 | 够：PS 5.1 下 `Attributes -band [IO.FileAttributes]::ReparsePoint` = True，能稳定识别这类条目；真 0 字节普通文件仍可被 F1 判据抓住 |
