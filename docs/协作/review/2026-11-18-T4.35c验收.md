## 三、代码核对（我读了 `task.html`/`style.css` 改动）

- `playerHtml(data)`：**`segments` 为 null 或 `[]` 直接返回空串**（不建 DOM，双降级）；非空才渲染 `#playerCard` + `<audio controls preload="metadata">` + `<ol>` 句子列表（每行 `mm:ss` + `escapeHtml(text)` + `data-idx/data-start`）。
- 签发：`postJson('api/v1/tasks/{id}/audio-token', {})` → `audio.src = resp.url`（**相对路径、不含 API_TOKEN**）；同一任务只签发一次，失败/过期**重签一次**，再失败就显示可读错误且**不阻塞原文/摘要/导出**；`audio error` 事件里做了"重签 + 等 `readyState>=1` + 恢复播放"（带 300ms 轮询与 `issueCount` 上限，不会死循环）。
- 点句：`ev.target.closest('.seg-line')` 取 `data-start` → `audio.currentTime = start` + `play()`（用户手势内，Chrome autoplay 未被拦——实测 `pausedBeforePause=false`）。
- 高亮：`timeupdate`/`seeked` 都走 `currentSegIndex(t)`（`start<=t<end`，**间隙取最近前一句**，首句前返回 -1 不高亮），只给命中的一行加 `.seg-current` 并移除其它，`scrollIntoView({block:'nearest'})`。
- 样式：`.seg-list` 限高可滚（420/390 时 320）、`.seg-current` 用 `--accent-tint/--accent-deep`、640 断点放大行高——复用现有变量、无 CDN、无框架。

## 四、残余风险（P3，接受不阻塞）

| 编号 | 说明 |
|---|---|
| P3-1 | `scrollIntoView({block:'nearest'})` 在"用户手动滚走了列表、但高亮句仍在页面内"时不会动；**但若高亮句已出列表可视区，每次切句都会把列表拉回当前句**——想边听边翻看别处的人会被轻微牵动，可后续加"用户滚动后暂停自动跟随 5s"的增强 |
| P3-2 | 句子列表在 DONE 后一次性渲染，**重渲染（如换模板/重跑后刷新）不保留滚动位置**、也不保留上次高亮位置（DONE 后不再轮询，日常无影响） |
| P3-3 | 无键盘快捷键（空格播放/上下句），属增强；`share.html` 播放器未做（卡面明确不动） |
| P3-4 | 高亮句切换的精度依赖 `<audio>` 的 `timeupdate` 频率（约 4Hz）；句边界跳变最多约 250ms 误差，肉眼可接受 |
| P3-5 | 签名 URL 仍在 DOM（`audio.src`）里——本来就是"可分享只读短时"设计；多用户隔离待 T4.37 把 userId 绑进签名 |
