## 2. T2.8 备份与恢复（通过，US-11 AC1 逐字满足）

**代码审阅**：`backup.ps1`（84 行）/`restore.ps1`（83 行），均 UTF-8 BOM、`$PSScriptRoot` 定位；`.gitignore` 加 `backups/`。
- backup：`pg_dump -Fc` 在容器内落盘再 `docker compose cp`（绕开 PowerShell 二进制重定向损坏）→ MinIO volume 用本机 `python:3.12-slim`
  打包 `tar -czf` → 采行数/对象数/大小/sha256 写 `manifest.json` → `-Keep`（默认 7）清理。
- restore：`-Force` 闸门（无则 exit 10）→ 校验三个文件存在且非空（否则 exit 11）→ 停 app → `pg_restore --clean --if-exists` →
  清空并解包 MinIO volume → 起 app → 按 manifest 逐表核对 + health → exit 14 表示自检不一致。

### 观察 F-2（P3，记录不修）

## 3. 缺陷/硬化项（唯一一条要动手的）

**F-4（P2 → T2.9）恢复脚本缺少"依赖未启动"的 preflight**：
把整栈 `docker compose stop` 后跑 `restore.ps1 ... -Force`，脚本走到 `pg_restore` 分支 **exit 12**，
但真实原因是 **postgres 容器没在运行**（`docker compose exec` 失败），提示文字"pg_restore 失败"**误导**；
失败分支还会去 `docker compose start app`（此时依赖全停，起了也白起）。
**数据没有损坏**（随后 `up -d` 起来 task=10 完好）。
建议在 restore 开头加 preflight：`postgres`/`minio` 必须 running，否则打印
"请先 `docker compose up -d postgres minio`（灾难后先让依赖起来，再恢复数据）" 并 exit 20。进 T2.9。
