## 三、修复方案（D-140 已定，方案 A）

1. `AudioDurationProbe`：先试 `format=duration`；**非数字/空/`N/A` 一律不抛**（改成返回 null 触发兜底）→ 兜底用 `ffprobe -select_streams a:0 -show_entries packet=pts_time,duration_time -of csv=p=0` 取**最后一个音频包的 `pts_time + duration_time`**；两路都拿不到 → **400 `INVALID_MEDIA`「无法解析媒体时长」**（不再 500）。每次 ffprobe 调用都保留 30s 超时。
2. 把"文本→时长"抽成**纯函数**（`parseFormatDuration` / `durationFromPackets`）便于单测，避免单测依赖宿主机 ffprobe（宿主机没有 ffmpeg，规范如此）。
3. 测试：纯函数矩阵（`"12.5"`/`"N/A"`/`""`/空白/`"12,5"`/多行 pts/空 pts）；E2E 增加 **webm 上传**用例（在 `app/src/test/resources` 放一个 ≤30KB 的 1–2 秒 webm fixture，从这次的 `recorded.webm` 用 ffmpeg 裁出来），断言 **201 + 最终 DONE + `duration_sec` 在 1–3 之间**（不是 500、不是 null）。
4. 不得改对外契约；`duration_sec` 语义不变（仍为四舍五入后的整秒，来源可以是 format 或兜底包时间）。
