## 4. 卡面外新缺陷 D1（P2，失败安全）→ 出卡 `T4.14b-fix`

**现象**：`download-model.ps1 -Force` 在 `models\hub\<repo>` 是 **junction / 符号链接**时崩溃：

```
Remove-Item : Object reference not set to an instance of an object.
At D:\new\projects\meeting-notes\scripts\download-model.ps1:52
（System.NullReferenceException；exit 1；链接未删；目标模型完好 483,546,902 B 不变）
```

**定位**：`download-model.ps1:52` 的 `if ($hubItem.LinkType) { Remove-Item $hubDir -Force }` —— PS 5.1 对 junction 调 `Remove-Item` 必抛 NRE（我已独立最小复现）。

**影响面**：仅命中"用户把已有 Hugging Face 缓存用 `mklink /J` 链进 `./models` 再执行 `-Force`"这一条路径。本工作区历史上正用过 junction 手法（`交付给WorkBuddy.md:153` 记录过同类用法），但 README/接入指南未推荐 junction → 判 **P2**（非默认路径 + 失败安全：不删数据、只是中断；但会向用户吐 .NET 栈，观感差，且失败提示语又在引导用户用 `-Force`）。

**候选修法（我已实证）**：`[System.IO.Directory]::Delete($hubDir)` 只删链接本身、目标完好（`Get-Item` 得 `LinkType=Junction`；同一 junction 上 `Remove-Item $j -Force` 必 NRE）。

**处置**：按 K-63（写码方不验收自己的代码，Lead 不写产品代码）**不自己改**，出卡 `artifacts/T4.14b/card-T4.14b-fix.md` 交写码方，一行改动 + 3 条验证。**不阻塞 T4.14b 合入**：卡面目标（F1 假完成）已达成，D1 是新增 `-Force` 的边界缺陷，且失败安全。
