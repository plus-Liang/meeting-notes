## 7. 发现（Follow-up，非本卡阻塞）

- **F-11（P2，T3.4/T3.8 处理）LOCAL 档在本机无法产出 `ai_tier=LOCAL`，两条失败路径已定位**：
  1. `LLM_MAX_TOKENS=8192`（F-8 的默认值）对 1.5B/CPU 过大：app 内调用 **124.9s 触顶**后抛 `RestClientException: Error while extracting response … content type [application/octet-stream]`（**误导性症状**：真实问题是等不到完整响应/响应不可解析；直连 ollama 同环境 HTTP 200 + `Content-Type: application/json`，22.2s 合法 JSON）。
  2. `LLM_MAX_TOKENS=512` 时 16.8s 可返回，但 1.5B **不遵守"只输出 JSON"**——输出前有散文 + 日期（"，然后在接下来的会议上…2023年1月15日"）、JSON 残缺 → 解析失败降级。
  **结论**：LOCAL 档需要"**本地档单独 max_tokens / 读超时预算**"（属新增配置键，须用户批准）+ "**从模型输出里抽取 JSON 子串**"的容错（T3.4）。当前级联兜底正确，用户可见结果为 EXTRACTIVE，不会 500/全空。
- **F-12（P3）**：`finish_reason=length` / 空 content 的 WARN 只有单测覆盖，实机未触发（云档本次未截断）→ T3.8 用长音频/低 max_tokens 反例补。
- **F-13（P3，建议 T4.12 死配置盘点一起看）**：`app.llm.ollama.*` 四个键从"死配置"变为消费方（T3.3 消化），但 `OLLAMA_ENABLED=true` 时**每任务**不再探活（启动缓存一次）——语义变化需在 README/配置清单写清"探活发生在启动期，运行中 ollama 掉线要靠级联降级兜底"。
