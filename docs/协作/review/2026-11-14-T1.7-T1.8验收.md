我用 `@Value("${...}")` / `getProperty(...)` 的实际消费集合，反查 yml 的 34 个 `app.*` 叶子键：

  `app.llm.fallback-extractive`、`app.llm.ollama.enabled`、`app.llm.ollama.base-url`、`app.llm.ollama.model`、`app.log-json`、
  `app.security.api-token`、`app.webhook.url`、`app.webhook.secret`、`app.webhook.max-retries`、`app.webhook.timeout-sec`、

### F-2（可接受，记录）状态机单测是"白盒直调"，未覆盖调用链

两条新用例用 `ReflectionTestUtils.invokeMethod(worker, "markFailure", ...)` **直接调私有方法**——这点作者主动说明了，且**没有为可测性改任何业务代码**（比改可见性好）。
代价：`process()` 抛异常 → `loop()` catch → `markFailure()` 这条**接线**不在单测里；如果有人删掉 `loop()` 里的 catch 调用，这两条用例仍然绿。
**为什么仍然放行**：这条接线**已被真机证据覆盖**——T1.5（停 ASR → 9s 走完 `RUNNING→RETRYING×2→DEAD`）与 T1.6（停 ASR → 8s `DEAD` + `error_code=ASR_ERROR`）都是真实走 `loop→process→throw→markFailure` 的路径。
**代价上限**：将来若重构 `loop()`，单测不会提醒。记为已知缺口，不单独立项（要补需把 `loop` 体抽成包私有方法 = 改业务代码，等 T2.2/T2.3 改动该文件时顺手做）。
