## 三、缺陷与观察

### P3-1（真缺陷，**不阻塞，要求下一张卡前置微修**）：空归一化摘要句被判成"命中"

- 复现（页面内直接调 helper）：`mnGroundSummaryWindow('。。', transcript)` 与 `('……', transcript)` → 返回 **hit=true**，并且 `fragment` 被填成原文第一句；原因是 `groundWindowBest` 里 `bigrams.length===0` 时走 `windowNorm.indexOf(norm) >= 0`，而 `norm=""` 时 `indexOf("")===0` → `rate=1`。
- 影响：若摘要里出现**仅标点**的片段（连续句末标点/"……"单独成段，LLM 输出偶发），会显示「第 N 句 ↔ 原文：…」这种**假依据**，违反 D-104"不误导"。现实数据当前未触发（237/256 的 0 命中都是真未命中）。
- 对照：既有 `mnGroundSentence` 开头有 `if (!normAction) return null;` 守卫，新 helper 漏了同款守卫 → **同一口径在两个实现间不一致**。
- 处置：立 **T4.23b** 微修卡（并入 T4.25 开工前置）：归一化后为空的摘要句一律 `hit=false`（显示"未找到直接依据"），不允许进候选；我复核时用注入探针断言 `'。。'/'……'` 不再出现 hit。
