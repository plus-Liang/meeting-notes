## 3. 我另外核出的两个问题（都出卡，不阻塞本卡）

### P2-1 全选态下行勾选框与计数不一致 → 卡 `T4.56`

- `rowHtml` `:364-365` 的 `checked` 只看 `state.checked[item.id]`；全选态下 `state.checked` 是空的 → **界面上所有行都显示未勾选**，但操作条写着「已选全部 N 条」。
- 此时点某行的勾选框（原为未勾）：`box.checked=true` → `state.checkedCount++`（`:541`），但 `state.selectAll` 仍为 `true`，该行的勾不影响操作集合（删除仍按全集）。
- 再点一次取消：`:542` `state.checkedCount--` → **`-1`**（之前计数是 0），`state.selectAll=false`。`render()` 里 `deleteBtn.disabled = count === 0 && !selectAll`（`:517`）→ `-1 !== 0` → **按钮仍可点**；点下去 `resolveSelectedIds()` 返回 `[]`（`:887-888`），`deleteSelected` 走 `:932` **静默清空、什么都不发生**。
- 影响：无数据风险，但"全选后想排除一条"会得到"选择全丢 + 点了没反应"，属于用户会报的那类坏体验。

### P2-2 `task.html` 三处原生 confirm 属同族 → 卡 `T4.57`

- `task.html:442`（按模板重新生成）、`:504`（撤销全部分享链接）、`:520`（删除任务）仍是 `window.confirm` —— 用户抱怨的"弹窗弄错了，应该在网站里的"在这三个入口原样存在。
- `confirmDialog` 目前是 `tasks.html` 内联函数，要复用需先抽成共享（`app.js` 或新 `confirm.js`），跨两个页面替换。
