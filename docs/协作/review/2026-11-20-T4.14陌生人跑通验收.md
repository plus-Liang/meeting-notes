## 3. 发现的问题

### F1（真实缺陷，产品脚本）模型下载「假完成」

- 现象：下载中断（SSL 错误）后重跑 `scripts/download-model.ps1`，输出 **「模型 small 已存在（…\snapshots），跳过下载」**；`first-run.ps1` 用同一判断（`snapshots` 目录非空即跳过）。
- 实证：此时 `snapshots/<rev>/` 下文件均为 0 字节占位（`model.bin` 缺失），直接起 asr 会进入重启循环，日志给出中文提示 + `[startup] 原始错误：The cached snapshot ... is incomplete: 1 file(s) are missing (model.bin)`。
- 影响：用户看到「已存在 → 跳过」会以为下载完成，接着看到 asr 不健康，排查成本高。
- 处置：出卡 **T4.14b**（`D:\new\artifacts\T4.14-stranger\card-T4.14b.md`），脚本属产品文件，按 K-63 交 WorkBuddy。

### F2（版本内容差异，非代码 bug）`v0.1.0` tag 的 `.env.example` 缺 3 个端口键

- 现象：按 README `git checkout v0.1.0` 后改 `MINIO_PORT`/`MINIO_CONSOLE_PORT` **不生效** → `Bind for 0.0.0.0:9000 failed: port is already allocated`。
- 根因：这 3 个键是 T4.13b（commit `01b4598`）才补进 `.env.example` 的，**晚于 `v0.1.0` tag（`1459d8d`）**；README 在 main 上先更新，tag 上仍是旧内容。
- 处置：README 已补注（用 tag 部署需手动追加，或改用 main）；彻底解决在下个版本发 tag 时带走。

### F3（观察，非缺陷）失败信息与降级路径

- 下载失败时脚本尾部输出中文降级建议，但 stdout 里同时冒出完整 Python traceback（`httpx2.ReadError`），对非技术用户偏吵。
- docker.io 认证端点 EOF 时 `compose pull` 会整体失败；README FAQ 已有 `REGISTRY_PREFIX` / `MINIO_IMAGE` 方案，本次实测有效（MinIO 换华为云镜像、postgres/redis 用 daocloud 镜像）。
