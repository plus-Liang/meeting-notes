## §6 建议（3 条，不阻塞）

- **S1（低，UX）**：`lockedException()` 文案写死 `lockoutMinutes`（「请 15 分钟后再试」），而 `remainingMinutes()` 在生产代码**零调用**（只有测试用）——临近解锁时提示不准确，且是死代码。建议：用 `remainingMinutes(lockedUntil)` 填充文案，并让 `lockedException` 接收 `Timestamp`；或删掉 `remainingMinutes`。
- **S2（低，策略）**：锁到期后 `failed_login_attempts` 仍停在 `max`，此时**任何一次**错误密码都会立刻再锁 15 分钟（真栈可复现：等到到期、手滑一次即锁）。对「按时解锁但手抖」的合法用户偏严。建议到期后顺手归零（`isLocked` 为 false 且 `locked_until` 非空时清零），或在 README 写明该语义（我已在报告里记录，卡面未要求）。
- **S3（信息）**：423 会暴露「该用户名存在且被锁」——这是与写码方确认后的**刻意取舍**（可用性优先；被锁本身已说明账号被盯上）。若要隐蔽，需统一 401 + 内部日志，代价是用户不理解为何进不去。**不改**，记入 D-228 的取舍栏。
