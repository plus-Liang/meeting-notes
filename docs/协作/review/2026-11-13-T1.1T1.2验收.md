## 2. 对"偏离指令"的判断：**接受，且是正确做法**

交付说明里主动报了一处偏离：minio 没走 `REGISTRY_PREFIX`，改用 `MINIO_IMAGE` 整体覆盖。我认可，理由：

- daocloud 对非 `library/` 命名空间走白名单，`minio/minio`、`ollama/ollama` 直接 `denied`；
- 单前缀模型**表达不了** "postgres 走 daocloud、minio 走华为云"这种混合来源，`MINIO_IMAGE`/`OLLAMA_IMAGE`
  是唯一不撒谎的抽象（空值时回落到官方名，不破坏他人使用）；
- 已实测可运行（minio healthy，且 `docker run` 验证过镜像没坏）。

已固化为 **D-038**。这是"配置全外置"原则（D-021）在镜像维度上的自然延伸，不是临时打补丁。

## 3. 发现的问题

### P3-1（建议，非阻塞）：空前缀时出现 `library/postgres:16-alpine`

`docker-compose.yml` 里写的是 `${REGISTRY_PREFIX:-}library/postgres:16-alpine`，前缀为空时得到
`library/postgres:16-alpine`。这个引用在 Docker Hub 上**能解析**（`library` 是官方命名空间），
所以不算错，但不是惯用写法，且个别第三方 mirror 可能不认 `library/` 前缀。
→ 处理：在 `.env.example` 注释里写清"留空时镜像名会带 `library/` 前缀，属正常"，或在 T2 整理 compose 时统一。

### P3-2（建议，T1.4 顺手改）：注释里的绝对路径会污染自检

`app/src/main/java/com/meetingnotes/MeetingNotesApplication.java:11` 的注释含 `D:\new\docs\...`。
`配置清单.md` §2 第 1 条自检会命中（"期望：无输出（或仅注释）"——属可接受，但让自检永远有一行噪音不好）。
→ 改成相对路径 `docs/项目/录音纪要平台/`。

### P3-3（建议，T3.3 做）：显式启用但无 key 的报错不友好

`LLM_ENABLED=true` + 无 key → 启动失败，异常是 Spring 原生的
`OpenAI base URL must be set. Use the connection property: spring.ai.openai.base-url`。
行为正确（显式优先），但用户看不出"你其实还缺 key"。→ EPP 里加一行 WARN 或自定义 fail-fast 消息。

## 4. 已入档的新坑（Lead 写入 `环境搭建说明.md` §7 + 代码仓 `AGENT.md` §4.1）

1. **daocloud 白名单只对 `library/` 友好**：`minio/minio`、`ollama/ollama` 被 `denied`；换华为云
   `swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/<image>` 实测可用（`dockerhub.icu` 会下到坏 blob，别用）。
2. **temurin 21 的 apt 源在 deb822 格式** `/etc/apt/sources.list.d/*.sources`：
   `sed /etc/apt/sources.list*` 里的 `*` 会匹配到**目录**，静默无效（还被 `2>/dev/null` 吞掉）。
   必须 `grep -rlE "archive\.ubuntu\.com|security\.ubuntu\.com" /etc/apt | xargs -r sed -i ...`。
3. **无 key 验证不许移 `.env`**（理由见 §1，假绿灯）。
4. **连库用 `-U mn`**，`postgres` 角色不存在。
5. Windows `docker run -v D:\...:/mig:ro` 会卡 `Created` → 用 `docker cp`（T0.5 已记，本次再次印证）。
