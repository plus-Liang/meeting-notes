## 3. 我发现的问题（都不阻塞本卡，但要留档）

**O1（P3，假阴性）跳过规则会连"真代码行"一起放过。** 跳过条件是 `Trim()` 后 `StartsWith('//'|'/*'|'*')` 或 `EndsWith('*/')`。我造夹具验证：

```js
alert('boom'); /* 这行是代码，只是结尾带块注释 */
console.log('visible')  /* 同样结尾带块注释 */
```

两条都**没被报**（exit 0）。今天真仓库风险为 0——静态目录里以 `*/` 结尾的行共 **334** 行，其中含三模式的只有 **1** 行，就是 `tasks.html:427`（块注释收尾行里的 `onfocus=alert(1)` 举例，跳过是对的）。但"代码行尾挂块注释"或"行首是 `*`（如 CSS 通用选择器）"会被整行放过，属于**静默盲区**。建议下一轮把它改成"跟踪块注释状态"而不是"看行首行尾字符"，或在报告里明确这是已知局限。

**O2（P3，同一规则的实例）** `style.css:233` 是真代码 `*, *::before, *::after {`（CSS 通用选择器），因为 `Trim()` 后以 `*` 开头，被当成注释行跳过。今天这行没有三模式所以无害，但它证明 `StartsWith('*')` 这个近似是有代价的。

**O3（事实更正）写码方回报"未 push（D:\new 非 git 仓）"** —— `D:\new` **是**本地 git 仓（`## main`、无远端），本次改动是**工作区未提交修改**，不是"非 git 仓"。语义差别影响后续交接：它会被我这次 commit 收进历史，而不是游离在版本控制外。

**O4（我自己的更正）** 我在第 95 份报告里把 `task.html` 记成 1396 行，**实测是 1393**（`ReadAllLines` 与 LF 计数都是 1393，无 CRLF）。写码方报的 1393 正确；这笔归我，已同步修正第 95 份报告。
