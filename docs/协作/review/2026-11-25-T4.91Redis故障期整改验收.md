## 五、建议（不阻塞）

- **S1**：卡面/文档的「长停恢复压到个位数秒」需按停机时长给区间——60s 停机 0.6–3.8s，120s 停机 6.6–10.8s（退避已到 cap 相位）。建议 `运维-监控与告警.md` 写「≤60s 停机：<5s；≥120s 停机：<15s」，避免运维误判。
- **S2**：`TranscriptionWorker.java` 恰 **300 行**（门禁硬上限），再无一行余量；建议下张小卡把 `sleepQuietly`/`abbreviate` 抽到独立类腾出空间。
- **S3**：`StalePendingSweeper` 与其它 Redis 调用点的故障 WARN 未去抖（120s 内 12 条），可评估复用 `RedisUnavailableReporter`（注意清扫器是 60s 一轮，窗口需独立）。
- **S4**：恢复 INFO 里的「期间抑制 N 条」只统计**最后一个窗口**（我的实测：INFO 报 1 条，而该次停机实际抑制 26 条），语义易误读；建议要么给累计抑制数，要么文案改成「本窗口抑制 N 条」。
- **S5**：worktree 场景的环境准备要写进卡面：需要主仓 `.env`（含 `API_TOKEN`，否则被 `WeakApiTokenGuard` 拒）、`ASR_MODEL_HOST_DIR` 挂模型、四个端口变量逐个 `$env:` export；另 `git status` 幻影 M 用 `git checkout -- .` 清。
