## 3. A2：真栈自愈——**卡面的 `docker kill` 验证不了自愈**

这是本卡最重要的一节，也是我这次差点被卡面误导的地方。

### 3.1 `docker kill` 属于「手动停止」，`unless-stopped` 按设计不触发

我在 `mn-t475l` 上实测：

| 时间点 | `State.Status` | `RestartCount` | `StartedAt` | `ExitCode` |
|---|---|---|---|---|
| 前 | running | 0 | 10:57:53 | 0 |
| `docker kill` 后 20s | **exited** | **0** | 未变 | 137 |
| 后 35s | **exited** | **0** | 未变 | 137 |

⇒ 卡面 A2 写的「`docker kill` 后 90s 内恢复」在 Docker 语义下**永远不成立**（`unless-stopped`/`always` 都把 `killed` 当人工停止）。写码方在同一天独立撞到这一点并主动上报，我复核后确认。

### 3.2 `docker exec kill -9 1` 也不成立（内核语义）

容器内 PID1 是 namespace init：对**未注册 handler** 的信号（含 SIGKILL 从同 namespace 发出）会被内核忽略，所以"进容器杀自己"这条常见做法无效。正确姿势是**让容器内进程自己退出**（进程正常终止，非 docker 手动干预），policy 才会介入。

### 3.3 用「进程自退」重验（我的实测数字）

| 服务 | 自退手段 | 观测 | 耗时 | RestartCount |
|---|---|---|---|---|
| postgres | `kill -s INT 1`（fast shutdown） | `die`→`start` | **1s** | 0→1 |
| redis | `redis-cli shutdown nosave` | `die`→`start` | **<4s** | 0→1 |
| minio | `sh -c "kill -s TERM 1"` | `die`→`start` | **1s** | 0→1 |
| app | `sh -c "kill -s TERM 1"`（走 T4.74 的 shutdown hook） | `die`→`start` | 容器 **1s** 起、health **UP** | 0→1 |

全部 < 90s 阈值；app 复活后 `/actuator/health` = `UP`。

## 8. 建议

- **OBS-1（中，部署链路）**：`tools\deploy-main.ps1` 只重建 app，**compose 级变更不会自动落地**。建议给脚本加 `-RecreateDeps`（或默认在检测到 compose 文件变化时对 `postgres/redis/minio` 做 `up -d`），并在冒烟里加一条「五个容器 `RestartPolicy` 与 compose 声明一致」的断言。这条不补，以后任何改 compose 的卡都会"验收通过、线上没生效"。
- **OBS-2（低）**：`docker-compose.yml` 多加了 2 行中文注释（超出卡面"只加 restart"的字面范围），无害，我接受。
- **OBS-3（低，文档）**：README 只写了"进程崩溃/宿主机重启/OOM 后自动拉起"，没写**怎么复现**。建议补一句：「注意 `docker kill` 与 `docker stop` 属人工停止，不会触发自愈；要验证自愈请让容器内进程自行退出（例如 `docker exec <c> sh -c 'kill -s TERM 1'`）」。否则下一个人还会用 `docker kill` 验出"没生效"的假结论。
