## 四、代码与卡面核对（我读了实现与三个测试文件）

- `UrlGuard`：纯逻辑 + 注入 `HostResolver`（单测 stub，不依赖真 DNS）；非 http/https、host 空、userinfo 全拒；**解析出的每一个 IP** 都要过网段判定（多 IP 里混一个内网也整体拒）；IPv4 按字节判（0/8、10/8、127/8、169.254/16、172.16/12、192.168/16、≥224）；IPv6 先解 IPv4 映射再判，ULA fc00::/7、fec0::/10、链路本地、组播、未指定都拒；**纯数字 IPv4 字面量在 Guard 内按 inet_aton 语义自规范化**（十进制/八进制/十六进制/缺段），仍是"算出真正会连的地址再判"，不是字符串黑名单；allow-hosts 只跳过 IP 拦截，不跳过 scheme/userinfo。
- `HttpMediaFetcher`：**手动**跟随 301/302/303/307/308 且**每一跳都重跑 UrlGuard**；超 `max-redirects`(5)→400；connect/read 超时→502；流式写盘边写边数，超 `max-bytes` 立即中止并删半截文件→413；`text/html`→400；**只发匿名 GET，不带 Cookie/Authorization**（单测断言确实没带）；`getResponseCode` 阶段超时也会删掉已建临时文件。
- `LinkTaskService`：与上传管线**同构顺序**（fetch → 只信文件头的 magic → 时长（复用 T4.30b 兜底）→ 幂等 `(user_id, content_hash)` → 配额按抓取时长 → MinIO → 入队），事务内失败整体回滚，临时文件 `finally` 删；DEAD 复活重投；worker 零改动。默认单用户与现网一致。
- 配置三处一致：`application.yml` 默认值 = `.env.example` = `配置清单.md`（5/5000/10000/209715200/空），`FETCH_ALLOW_HOSTS` 默认空且三处都写了"生产必须留空、否则 SSRF 防护被绕过"。
- 单测 22 例我逐个读过：断言固定状态码/错误码、失败后**文件不存在**、每跳拦截、`text/html`、超大小、无 cookie/auth、缩写数字 IP、解析失败 502 —— 不是空壳测试。
- **一处卡面偏离（我判定接受）**：卡面逐字写 `source_type='LINK'`，而 V1 schema 注释预留值是 `FETCH`；**无 CHECK 约束**，按卡执行，`接入指南 §3.9` 已如实写明命名漂移。

## 五、我改了一处文档口径（不改产品）

§3.9 原文"十进制/八进制/十六进制缩写（`2130706433`、`0177.0.0.1`、`0x7f.0.0.1`、`127.1`）会被解析器归一化后拦截"不精确：实测 `0x7f.0.0.1`/`127.1` 是 JDK URI **直接判 host 非法**、更早被拒；只有十进制/八进制形式走 Guard 自规范化。两种路径**结果一样是 400 `URL_BLOCKED`**，但文档要如实。已改成"两种路径都写明"，避免接入方以为 `0x7f` 形式被归一化。
