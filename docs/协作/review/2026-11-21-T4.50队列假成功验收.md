## 4. 新发现的坑（已写入 K-109）

写码方和我都撞到同一现象：探针按「上一个 id + 1」猜任务 id 会指到不存在的行。原因：**`INSERT … ON CONFLICT DO NOTHING` 冲突不插行，但 PostgreSQL 的 sequence 照常递增**，于是 C 场景里 `id=3` 被幂等重传烧掉，真实任务是 `id=4`。
→ 口径：**验收探针取任务 id 只查 DB（`select id from task order by id desc limit 1`），不要自增猜**；此类"序列号空洞"不是缺陷，但会让断言打在空气上（表现为"任务查不到"而不是"失败"）。
