## 三、静态与代码审查（我逐行读）

**编码**：新建/改动的 Java、`setup.html`、`application.yml`、`first-run.sh` 均 UTF-8 **无 BOM**、**CRLF=0**；`first-run.ps1` **BOM=239,187,191** 保留（PS 5.1 中文必需，K-102）。

**`SetupController`**：`requireUnclaimed()` 判据只认 `authService.adminClaimed()`（与登录同源），已认领抛 `NoResourceFoundException` → 经 `ApiExceptionHandler.onUnexpected` 落到 **404 `NOT_FOUND`**（我核过 handler 里对 `NoResourceFoundException` 有显式分支，且它是 `ErrorResponse` 接口实现，不会落成 500）；`/setup` 与 `/setup.html` 双路径显式映射，controller 映射优先于静态资源 handler；未初始化时从 `classpath:static/setup.html` 回源（不含数据，数据全由三个接口给）。

**`SetupChecks`**：五项各自 `try/catch`，`runAll()` 顺序 postgres/redis/minio/asr/disk；DB 用**独立** `JdbcTemplate` 且 `setQueryTimeout(3)`；Redis 用 `RedisCallback` 显式 `conn.ping()` 规避二义 + 复用 `REDIS_TIMEOUT(3s)`；MinIO `headBucket` 带 `apiCallTimeout(5s)`；ASR 用独立 `SimpleClientHttpRequestFactory` 5s 超时 + `RestClient`，失败返回 `ready:false`**不抛 500**；`detail` 里**没有** URL/IP/端口/凭据（ASSERT 于我的 A1/A2 输出）。

**`AuthService`**：`register()` 首行加 `if (!adminClaimed()) throw 403 SETUP_REQUIRED`（认领路径从注册移除）；`setupClaimAdmin()` 四步（409 已认领 → 403 码错 → 原子条件更新 0 行 → 409 → 成功返回 ADMIN 会话）；`setupCodeValid()` 用 `ApiTokenFilter.constantTimeEquals`（`MessageDigest.isEqual` 对 UTF-8 字节），配置为空**恒 false**；`claimAdminIfUnclaimed` 的原子 SQL 语义（`WHERE id=1 AND password_hash=UNCLaimed`）未变——安装码是它**前面**的闸。

**`ApiTokenFilter`**：只加 3 条精确匹配（`GET /setup/status`、`GET /setup/model`、`POST /setup/admin`），**没有**前缀通配。

**`RateLimitInterceptor`**：只加 1 行 `case "/api/v1/setup/admin" -> Bucket.REGISTER`，未新增桶、未改构造参数。

**`setup.html`**：0 处 `innerHTML` 拼服务端数据、0 处 `window.confirm/alert/prompt`（只有一行注释提到名词）；令牌写 `mn_token`/`mn_user` 与 `auth.js` 同键；404 时落到 `scrLocked`「本实例已完成初始化」。

**`login.html` / `auth.js`**：`adminClaimed===false` 时显示向导链接、隐藏并禁用注册入口、`setMode('login')` 兜底；`auth.js` 的 401 跳转例外名单加 `setup.html`（否则向导页会被踢回登录页）。
