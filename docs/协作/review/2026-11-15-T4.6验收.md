## 5. 代码核对（不是只看它绿）

- **DONE 时序不受影响（D-069）**：worker 在 `UPDATE … status='DONE'` **之后**才调 `onTerminal`，且 `onTerminal` 内部 try/catch 全兜、只做"查 URL + 插一行 + 丢线程池"，毫秒级；我复跑 220 条测试与 task 177~179 的 DONE 时间戳均正常。
- **不重复投递**：`attempt()` 先用 `UPDATE … SET attempts=attempts+1, next_retry=NULL WHERE id=? AND next_retry IS NOT NULL RETURNING …` **原子认领**，被扫描/初次投递重复提交时第二个拿不到行直接返回（我两次重试实验未见双投）。
- **结束条件正确**：`nextBackoffSec(attempts, maxRetries)` → 1/10/60，第 4 次失败返回 null → 置 `next_retry=NULL` 终局（与 §4.2/§4.3 实测吻合）。
- **重试扫描可恢复**：`@Scheduled(fixedDelay=1000)` + `next_retry<=now()` 扫描；`MeetingNotesApplication` 已有 `@EnableScheduling`；H2 测试上下文无表时 `catch` 到 debug（不刷 ERROR）。
- **安全**：签名对**实际发送的 body 字节**计算（同一 `byte[]`），无 secret 日志；`OFFLINE_MODE` 与空 secret 都是"不投递"安全默认。
- **测试质量**：`ApiTokenFilterTest` 用 standalone MockMvc（不拉全上下文），覆盖缺/错/对/小写 bearere + 常量时间；`WebhookDeliveryServiceTest` 用独立 HMAC 实现**互证**签名（不是自证）、钉死九键与退避档位。
