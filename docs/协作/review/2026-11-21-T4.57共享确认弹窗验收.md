## 3. 唯一 FAIL → 卡面外真缺陷（P2，出卡 T4.58）

`pageerror: TypeError: resp.json is not a function @ task.html:543:21`。根因：`app.js:125-136` 的 `sendJson()` 已经把响应解析成数据对象（附加 `__httpStatus`）返回，但 `task.html` 有两处仍把它当 `Response` 用：

- `:539-549` 删除：`sendJson('api/v1/tasks/' + id, 'DELETE').then(function (resp) { if (resp.status === 200) { window.location.href='tasks.html'; … } else return resp.json().then(...) })` → `resp.status` 是 `undefined`，不跳转；落到 `resp.json()` 直接抛 TypeError。
- `:594-599` 导出：`if (resp.status !== 200) { return resp.json().then(...) }` → 失败分支同样抛错，用户看不到错误文案。

**用户可见后果**：在详情页确认删除后，**服务端确实删了**，但页面不跳转、删除按钮永久置灰、控制台报错——用户以为"点了没反应"；导出失败时同样没有文案。其余 **20+ 处**（`:171/178/386/404/452/491/517/866/1239/1299/1316`）都正确使用 `__httpStatus`，所以是两处漏改，不是全局口径问题。

修法（卡面已写）：`resp.status → resp.__httpStatus`、删掉重复的 `resp.json()`（改用 `resp.code`/`resp.message`）、删除成功必须跳转、导出失败必须给文案。
