## 五、代码与卡面核对（我读了实现与测试）

- `infra/asr/server.py`：生成器只消费一次（边遍历边收集，修掉了"先 join 再取 segments 会消费空"的隐患）；**`text` 拼接口径与旧版逐字一致**（`segment.text` 原样连接，不去空白）；`segments` 取 `round(start/end,3)`、text `strip()`、空白句丢弃；空音频 → `[]`；三键不动。
- `AsrResponseParser`：**纯函数不抛**；无 `segments` 键/非数组 → `null`（旧响应语义）；`[]` → 空列表；负数 / `end<start` / 非数值元素丢弃；blank text 保留并 strip；非 JSON → `text=null` 由调用方按 `ASR_ERROR` 处理；`toJson` 失败降级 null 不抛。
- `AsrClient`：`RestClient` 复用 `AsrHttpClientConfig` 的 base-url 与 URI 路由超时（`/v1/audio/transcriptions` → 900s）；multipart 同既有请求；**一次调用同取 text+segments**；不可解析 → `IllegalStateException` → worker 包成 `ProcessingException("ASR_ERROR")` 走既有重试/死信（语义未变）。
- `TranscriptionWorker`：`finalizeResult(taskId, text, segments)`；PASTE 显式传 `null`；`saveTranscript` 用**同一条 upsert** 写 transcript+segments（`?::jsonb`）；**DONE 仍最后写**（D-069）；`ProcessingException` 提为同包独立文件（**语义逐字不变**，只为过 M3 300 行）。
- `TaskController`：详情 SQL 用 `CASE WHEN status='DONE' THEN r.segments::text END`（非 DONE/旧任务 natural null）；解析失败 → null 不炸接口；响应 15 键**只增在第 15 位**（`TaskStatusResponseTest` 断言键序与元素键 `start/end/text`）。
- 测试非空壳：`AsrClientTest` 用本地 HttpServer 验"单响应解析/不可解析走 ASR_ERROR 路径/老三键兼容"；parser 9 例矩阵；worker 新增"segments 与 transcript 同 upsert 且 DONE 最后"；E2E `n` 断言有序/非空/末段容差、`o` 用 **`before_id=300` keyset** 取历史任务（不再依赖默认列表窗口）。
