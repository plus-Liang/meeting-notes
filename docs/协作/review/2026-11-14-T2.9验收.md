## 2. 三个要动手的问题（→ T3.0）

**F-5（P1，测试入口干净 shell 必红）**：`scripts/test.ps1` 先把 `.env` 的 `ASR_BASE_URL=http://asr:8000`（**容器内地址**）注入进程，
再判断"外部已设置就以外部为准"——于是**宿主机解析不了 `asr`**，`AsrSmokeTest` 必挂；连外部显式设 `ASR_BASE_URL`
也会被 `.env` 覆盖。**也就是说卡片里"50/50 exit 0"在当前仓库状态下不可复现**（我上一轮 T2.7/T2.8 的 50/50 是 shell 里恰好有值的旧状态；
本轮我实测两次全量都红）。修法：注入 `.env` 时**跳过 `ASR_BASE_URL`**（容器地址不该进测试进程），一律用 `localhost:${ASR_PORT}`，
并打印最终值；冒烟反例（故意设错端口）仍要能造红。

**F-1b（P2，控制台中文仍乱码）**：`pom.xml` 的 surefire `argLine=-Dfile.encoding=UTF-8` 只作用于 **fork 的测试 JVM**，
maven 父进程仍按系统编码转发 → 中文行依旧 `����`。修法：`test.ps1` 里同时设 `$env:MAVEN_OPTS="-Dfile.encoding=UTF-8"`（或改 surefire 输出重定向），
验收要贴**中文行可读**（例：`worker 已启动`、`转写结果已落库`）。

**F-6（P2，配额日切时区错位）**：配额日 = PG `CURRENT_DATE`（容器 UTC），`Retry-After` = JVM `LocalDate.now()`（容器 UTC），
两者一致但都是 **UTC**——中国用户实际在**早上 8 点**重置，弹窗却说"明天再试"（`Retry-After: 64852s` ≈ 18 小时）。
**口径正确、体验错位**：建议 compose 给 `app`/`postgres` 显式 `TZ: ${TZ:-Asia/Shanghai}` + `.env.example` 加 `TZ`，
同时更新 `配置清单.md`。（改 compose 属公共面，已报备，需人类点头。）
