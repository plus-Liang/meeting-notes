### 实验① `--scale app=2` 在标准 compose 下必失败（A3）

```
docker compose -p mn-t488x -f docker-compose.yml up -d           # 单副本起得来

```
✅ 与交付方原文同因同义；根因 `docker-compose.yml:127` 固定宿主映射。

### 实验② 两副本 20 条任务每条只处理一次（A4）

nginx 入口 `POST /api/v1/tasks` × 20（全部 **201**），等任务完成：
```
status | count
 DONE  |    21      # 20 条本轮 + 1 条我先前建的夹具
mn-t488l-app-1 start_lines= 9  distinct= 9
mn-t488l-app-2 start_lines=11  distinct=11
total_start_lines= 20  distinct_tasks= 20  offenders= {}  all_exactly_once= True
```
✅ 两副本真实分工（9/11），**没有一条被处理两次** ⇒ 条件 UPDATE 认领跨副本正确（「已具备」栏成立）。

### 实验③ webhook 重复投递（A5，关键项）

装置：先插 **20 条**到期 `webhook_delivery` 行（`next_retry=now()`），probe 对每次 POST 记 `delivery_id` + 时间；两副本各 1s 扫一次。

```
total hits 56
delivery d8950a2b-…  hits=3 t0=740.547 gaps=0.017,10.859      ← 17ms 内重复投递
delivery a889acd6-…  hits=3 t0=740.414 gaps=1.180,10.886
…（其余 18 条：hits=2~3，gap 均在 1.0~1.9s / 10.1~10.9s 的退避节奏上）
```
**结论：重复投递确实存在，但是概率事件**（20 条里 1 条出现 17ms 双投；此前 3 条样本一次没出现）。结合代码可精确定位机制（见 S1）：`attempt()` 的认领守卫是 `WHERE id = ? AND next_retry IS NOT NULL`（`:145`），**只要求「非空」而不要求「已到期」**；副本 B 的 `SELECT`（`:119`）拿到的是命中前快照，等 A 失败后 `recordAttempt` 把 `next_retry` 写回 `now()+backoff`，B 的 `UPDATE` 仍满足 `IS NOT NULL` 从而**再投一次**——于是接收方在毫秒级收到两次同一事件。

### 实验④ 限流倍数（A6）

同一 key（nginx 容器 IP），对不存在用户名连打 24 次错密码（避开 T4.81 账号锁定）：

```
单副本：401 ×10 → 第 11 次 429            （first429=11）
两副本：401 ×20 → 第 21 次 429            （first429=21）
```
✅ 精确 2 倍 ⇒ 限流桶在 JVM 内、全局上限 ≠ 配置值，清单「④ 限流全局计数」判定成立。
（交付方原文是「放过 ~17 次」，方向对但值偏保守；我的样本更干净，理由见 S3。）

## 六、建议（S1–S4，均不阻塞）

- **S1（文档精度，建议下轮文档卡消化）**：清单 §2/§5 对 webhook 重复的机制描述是「两副本会同时捞到同一批 id」。我的实验表明真正的窗口是 **认领守卫不校验「到期」**（`:145` 只有 `next_retry IS NOT NULL`）——建议清单写明这一点，并把修法从「FOR UPDATE SKIP LOCKED」补充为更小改动即可的 **`AND next_retry <= now()`** 守卫（配合 `SELECT … FOR UPDATE SKIP LOCKED` 或条件 UPDATE 影响行数=1 均可）。
- **S2（证据解读）**：「重复投递」是概率事件（我 20 行样本 1 行复现、3 行样本 0 行），建议证据里保留「样本量 + 命中数」而不是只写一句「复现」，避免后人以为稳定必现。
- **S3（数字口径）**：限流倍数建议直接写实测点（单副本第 11 次 / 两副本第 21 次 = 2×），比「~17 次」更可复核。
- **S4（补一句量化边界）**：worker 是单线程（`TranscriptionWorker.java:77,103`）⇒ 副本数即并发上界；建议在 §3 ⑤ 明确「N 副本 ≈ N 路并行 ASR，ASR 单容器是瓶颈」，与「未验证」的正确态度一致。
