## 五、建议（S1–S5，均不阻塞）

- **S1（低）** `settings.html` 的 401 分支实际是死路径——`auth.js:61` 的 `apiFetch` 遇 401 已跳登录页；且 5 行标记与顶部重复。建议下次合并成模板函数（不影响行为）。
- **S2（低）** 网络完全失败时 `getJson` 返回 `{__httpStatus: 0}`，五格仍显示「未知」，未区分「服务不可达」与「状态未知」。可后续用「服务未响应」文案。
- **S3（低）** `TaskDeleteService:151-153` 取 `source_uri` 的第二条 SELECT 仍未带 `deleted_at IS NULL`——事务内已被前置 `FOR UPDATE` 保护，但属同族条件不全，下次顺手补齐。
- **S4（中）** 批量删除（`POST /tasks/delete`）里已在回收站的 id 现在会呈现 `NOT_FOUND`；前端 `tasks.html` 的「已删除 N 个」如何归类未在本卡覆盖，建议下张前端小卡核对文案，别让用户以为删除失败。
- **S5（低）** 导出默认变更属**行为变更**（外部脚本若依赖旧默认会静默少/多一节）；已在 `接入指南.md` 写明，但 Release note 里也应有一句。
