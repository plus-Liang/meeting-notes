**P1-1（阻断，实测证据 `artifacts/T4.29/lead-verify/p1-405.txt`）**：
```
REQ  GET  /api/v1/tasks/237/meta  -> 200 {"task_id":237,"labels":["课程","面试"],"favorite":true}
REQ  POST /api/v1/tasks/237/meta  -> 405 {"code":"METHOD_NOT_ALLOWED", ...}
chipsAfter = ['课程 ×','面试 ×']            ← 新增标签「复核」没有出现
metaMsg    = 保存失败（METHOD_NOT_ALLOWED）   ← 点星标同样 405
```
根因：`static/task.html` 的 `updateMeta()` 调 `postJson(...)`，而 `app.js` 的 `postJson` **固定 `method: 'POST'`**；后端是 `@PatchMapping` → 405。
反证（`proof-sendjson-patch.txt`）：在同一个页面里手工调**已有的** `sendJson('api/v1/tasks/237/meta','PATCH',{...})` → **200**，读回 `labels/favorite` 正确。即后端没问题，**修法就是把这一处换成 `sendJson(url,'PATCH',body)`（1 行）**。

**P2-1（下拉滞后 + 可能卡筛选）**：`renderFilterBar()` 只在初始化、`fetchCounts()`（30s 轮询）、筛选点击时调用，**数据加载后的 `render()` 不调用它** → 刚进页面时下拉只有「全部标签」，标签选项最多滞后 30s / 下次交互才出现（我实测：点★收藏筛出 237 后，下拉仍缺「课程」，再隔一次交互才出现）。边界：若 `state.filterLabel` 已不在 options 中，下拉显示「全部标签」但筛选仍生效，用户可能看到空列表却找不到清除入口（刷新可恢复）。
