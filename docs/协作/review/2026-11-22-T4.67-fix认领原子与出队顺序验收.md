### 2.1 我上一轮漏读 M3（我方失误，记 K-133）

第 104 份 C1 我写「门禁仅 M9 一条阻塞」，真实输出还有 **M3（`TranscriptionWorker.java` 301 行 > 300）**；我没看到是因为把输出接了 `Select-Object -Last 3`，M3 在更前面被截掉。写码方本轮主动核对并指出，且把文件压回 299 行。

**修正口径**：门禁/测试输出取证一律落盘全文再解析（`| Tee-Object`），不得只取尾部若干行；任何「仅 N 条」的结论必须能指到全文里的那 N 行。

### 2.2 写码方超出卡面的改动（接受）

删掉 `TranscriptionWorker` 里被条件 UPDATE 完全覆盖的 5 行状态预检查——不在 F4 字面要求内，但属同一能力的两套 fallback，留着会让 `selectById` 语义与认领语义分叉。它提前声明了理由，我核对后认为方向正确且被 M3 变异（`:claimConflict…` 3E）与真栈 F4 双重证明，**接受**。

### 2.3 它自曝的两个环境坑（记 K-134 / K-135）

- **H2 `TIMESTAMP(6)` 截断**：`Instant.now()` 的亚微秒精度写入 H2 被截到微秒，导致「恰好等于 cutoff」的行变成严格小于 → 用例抛硬币；修法是把 `updated_at` 截齐毫秒再写。
- **Mockito 严格桩**：共用 `opsForList()` 桩在 null-key 用例里永不被消费 → `UnnecessaryStubbing` 失败；修法 `lenient()`。

### 2.4 变异装置事故（我方，记 K-133 同条）

首版变异脚本用 `$ErrorActionPreference='Stop'`，mvn 往 stderr 写 WARNING 触发 `NativeCommandError`，脚本在「已写入变异、未还原」处中止，**工作树残留 `DESC` 变异**。改用 `try/finally` 强制还原后才继续；任何变异测试必须保证还原在 finally 里，且跑完核对 `git status` 干净。
