### 关键判断

- **D/E/F/G 是"零成本覆盖"**：同一管线 + 4 个摘要模板（会议 / 课程 / 访谈 / 播客）。成本 3h，收益是潜在用户面翻倍。
- **I 医疗**：能做**技术**，但**不做合规背书**——README 必须明说"本项目无医疗/法律合规认证，合规责任在使用方"。这条写进"明确不做"，避免被误用。
- **J 销售质检**：需要电话录音批量接入 + 违禁词库 + 质检报表，是另一个产品，v1 不做（写进 backlog，不是悄悄忽略）。

## 3. 八个输入入口

| # | 入口 | 形式 | 优先级 | 成本 | 坑 |
|---|---|---|---|---|---|
| 1 | **UPLOAD** | 本地音视频文件（格式见 §4） | **P1** | 已有 | 校验按文件头 |
| 2 | **FETCH** | http(s) 直链 | **P1** | 已有 | SSRF 防护 |
| 3 | **PASTE** | 文本 / srt / vtt / **ass** | **P1** | 已有（+ass 解析） | 编码识别（UTF-8/GBK） |
| 4 | **INBOX** | 宿主目录轮询 | **P2**（原 P1，为让时间盒下调） | 2h | 增量与去重 |
| 5 | **RECORD** | 浏览器标签页/屏幕录制 | **P2** | 4h | 仅桌面 Chrome/Edge；DRM 黑屏 |
| 6 | **RSS** | 播客订阅 feed（`enclosure` 直链） | **P2** | 3h | 只取最近 N 集；去重 |
| 7 | **MCP** | AI agent 直接调工具 | **P3** | 4h | 协议版本演进 |
| 8 | **OCR 补充** | PPT 截图 / 板书照片，与转写**合并**成完整讲义 | **P3** | 6h | 需要图文对齐算法 |

### 明确不做（写进 spec §8）

| 不做 | 理由 |
|---|---|
| 微信语音 `silk` 格式 | 需专门解码库（libsilk/pilk），ffmpeg 原生不支持，性价比低 |
| B站 / YouTube **页面**链接 | 非直链；抽流违反平台条款 |
| 网盘分享链接 | 需登录态与鉴权 |
| 会议**实时入会**（腾讯会议/飞书/Zoom bot） | 需 SDK/机器人，规模不匹配。**只支持导出后的录制文件** |
| 手机 share sheet / 系统级录音 App | 需要做客户端，违反"Web 交付"约束 |
| 电话录音批量接入（销售质检） | 是另一个产品（需要 PBX/运营商录音对接） |

## 4. 格式支持清单（显式列出，不靠"应该能解"）

容器内有 ffmpeg，理论上能解的都行。但**对外承诺必须显式**：

**音频（8）**：`mp3` `wav` `m4a` `aac` `flac` `ogg` `opus` `amr`
**视频（6）**：`mp4` `mov` `mkv` `avi` `flv` `webm`
**文本（4）**：`txt` `srt` `vtt` `ass`

- `amr` 是微信/老手机录音的常见格式 → 必须支持（学生、律师常用录音笔导出 amr）；
- `opus` 是微信新语音、Telegram 语音、浏览器录制的容器格式 → 必须支持；
- 超出清单的格式：接受上传但**明确告知"可能失败"**，失败时给"请转成 mp3"的建议，而不是静默卡住。
