### 1.4 AI 三档（**模型名与 key 全在这里**，见 D-020）

| 环境变量 | 档位 | 作用 | 默认值 |
|---|---|---|---|
| `LLM_BASE_URL` | ①云 API | 兼容地址（DeepSeek/智谱/Kimi/通义），**不带 `/v1`** | 空 |
| `LLM_API_KEY` | ①云 API | 密钥 | 空 |
| `LLM_MODEL` | ①云 API | 模型名（T0.5 实测 `deepseek-flash`） | 空 |
| `LLM_ENABLED` | ①云 API | 开关；**空 = 按是否填了 key 自动判断**（D-035），true/false 强制 | 空 |
| `LLM_CHAT_COMPLETIONS_PATH` | ①云 API | chat 端点路径；DeepSeek/OpenAI 用 `/v1/chat/completions`，智谱用 `/chat/completions` | /v1/chat/completions |
| `LLM_MAX_TOKENS` | ①云 API | 单次最大输出 token；thinking 模型给太小会返回**空 content**（1024 必空、4096 不稳，**8192** 才稳，D-071）。`application.yml` 默认值已在 **T3.3（F-8）** 改为 **8192**，`.env`/`.env.example`/yml 三处一致 | **8192** |
| `LLM_TIMEOUT_SEC` | ①云 API | chat（结构化：摘要+关键词+待办**一次**调用）**读超时**；按 URI 路由，与转写 900s 互不串（T3.1/D-068）：LLM 挂死最多拖住 worker 120s | 120 |
| `OLLAMA_ENABLED` | ②本地 | 是否启用本地 LLM（默认关；`docker compose --profile local-llm up -d ollama` + 导入模型后才可开）。**探活只在启动期做一次（≤2s）**，运行中掉线靠级联降级兜底 | false |
| `OLLAMA_BASE_URL` | ②本地 | Ollama 地址（OpenAI 兼容层，base 已含 `/v1`） | http://ollama:11434/v1 |
| `OLLAMA_MODEL` | ②本地 | 模型名（本机实测 `qwen2.5:1.5b`）。⚠️ 该小模型 + 全局 `LLM_MAX_TOKENS=8192` 会超 120s（F-11）；**已批准**本地档用下面两个独立键（D-081） | 空 |
| `LLM_LOCAL_MAX_TOKENS` | ②本地 | 本地档单次最大输出 token，**独立于云档**（D-081/F-11）：默认 512（实测 512 约 16.8s 返回；8192 会 >120s 触顶） | 512 |
| `LLM_LOCAL_TIMEOUT_SEC` | ②本地 | 本地档 chat 读超时（秒），**独立于云档 120s**（D-081/F-11）：CPU 慢，给宽松值 | 180 |
| `EXTRACTIVE_FALLBACK_ENABLED` | ③兜底 | 抽取式摘要（零依赖） | true |

> ⚠️ **本地档 v1 已知限制（F-14，D-089）**：本机实测 `qwen2.5:1.5b` **不可用**——512 被截断 / 1024 不截断但输出多个 JSON 对象拼接且漏 todos / 2048 又被 `finish_reason=length` 截断。
> 结论是**模型不守结构约束且输出随预算膨胀，不是预算问题**；失败会自动降级 EXTRACTIVE（任务仍 DONE、`ai_tier=EXTRACTIVE`）。
> 因此这些键保留为"实验档"：**默认关**（`OLLAMA_ENABLED=false`、`OLLAMA_MODEL` 空），不会影响别人的开箱体验；要质量请用云档（①）。换更守约束的模型属 v2，不在 v1 承诺内。

**选择顺序（代码里必须按此顺序）**：①有 key → 用云；否则 ②启用且可用 → 用本地；
否则 ③抽取式。**三档都必须能产出 spec 要求的字段，只是质量不同。**

## 2. 硬编码自检（每个任务的 DoD 都要跑）

```powershell
cd D:\new\projects\meeting-notes

# 1) 代码里不应出现本机绝对路径 / 回环地址 / 明文 key
Select-String -Path .\app\src\main\java\**\*.java -Pattern 'C:\\','D:\\','localhost','127\.0\.0\.1','sk-','minioadmin'
# 期望：无输出（或仅注释）

# 2) yml 里每个值都应是 ${ENV:default} 形式
Select-String -Path .\app\src\main\resources\application.yml -Pattern '^\s+\S+:\s+(?!\$\{)[^\s#]'
# 期望：只命中 server.port 之外的极少数固定项，逐行确认

# 3) 新增配置项必须在 .env.example 里有对应行
#    允许出现"只在 .env 里、yml 里没有"的项（它们由 docker-compose 消费，不进应用配置）：
#    ASR_IMAGE / ASR_PORT / INBOX_HOST_DIR / POSTGRES_DB / POSTGRES_USER / POSTGRES_PASSWORD
$allowed = @('ASR_PORT','INBOX_HOST_DIR','POSTGRES_DB','POSTGRES_USER','POSTGRES_PASSWORD',
             'REGISTRY_PREFIX','MINIO_PORT','MINIO_CONSOLE_PORT','OLLAMA_PORT','MINIO_IMAGE','OLLAMA_IMAGE',
             'ASR_MODEL_HOST_DIR','PIP_INDEX_URL',
             'ASR_MODEL_NAME','ASR_LANGUAGE','ASR_COMPUTE_TYPE','ASR_BEAM_SIZE','ASR_SMOKE_AUDIO','FFPROBE_BIN')
$yml = (Select-String -Path .\app\src\main\resources\application.yml -Pattern '\$\{([A-Z0-9_]+)' -AllMatches).Matches |
        ForEach-Object { $_.Groups[1].Value } | Sort-Object -Unique
$env = (Select-String -Path .\.env.example -Pattern '^([A-Z0-9_]+)=' -AllMatches).Matches |
       ForEach-Object { $_.Groups[1].Value } | Sort-Object -Unique
Compare-Object $yml $env | Where-Object { $allowed -notcontains $_.InputObject }
# 期望：无输出（yml 用到的变量都在 .env.example 里；多余项只能是 $allowed 那几个）

# 4) 反向：.env 里定义了但两处都没用到的死配置
$x = (Compare-Object $yml $env | Where-Object { $allowed -notcontains $_.InputObject })
if ($x) { $x | Format-Table -AutoSize } else { 'no diff' }

# 5) 死配置反查（D-054）：yml 里的键到底有没有人用？
#    上面 3/4 只查「yml ↔ .env 是否对齐」，查不出「配置项没人消费」——必须反查 Java 消费方。
$appKeys = @('app.base-url','app.offline-mode','app.task.max-duration-sec','app.task.max-size-bytes','app.task.max-retries',
  'app.media.ffprobe-bin','app.media.ffmpeg-bin','app.worker.queue-key','app.worker.poll-timeout-sec',
  'app.asr.max-concurrency','app.asr.timeout-sec','app.asr.connect-timeout-sec','app.asr.max-segment-sec','app.llm.enabled','app.llm.fallback-extractive',
  'app.llm.timeout-sec',
  'app.llm.ollama.enabled','app.llm.ollama.base-url','app.llm.ollama.model','app.log-json','app.storage.endpoint',
  'app.storage.access-key','app.storage.secret-key','app.storage.bucket','app.storage.region','app.storage.path-style',
  'app.security.api-token','app.quota.minutes-per-day','app.quota.tasks-per-day','app.webhook.url','app.webhook.secret',
  'app.webhook.max-retries','app.webhook.timeout-sec','app.inbox.enabled','app.inbox.dir','app.inbox.poll-sec')
$used = @()
Get-ChildItem -Recurse .\app\src\main\java -Filter *.java | ForEach-Object {
  $t = [IO.File]::ReadAllText($_.FullName, [Text.Encoding]::UTF8)
  # 消费方式①：@Value / ${...} 占位符
  [regex]::Matches($t, '\$\{([a-zA-Z0-9._-]+)') | ForEach-Object { $used += $_.Groups[1].Value }
  # 消费方式②：Environment.getProperty("app.x")（T2.7 的 log-json 走这条，旧口径漏了 → 误报死配置）
  [regex]::Matches($t, 'getProperty\("([a-zA-Z0-9._-]+)"') | ForEach-Object { $used += $_.Groups[1].Value }
}
$appKeys | Where-Object { $used -notcontains $_ }
# 期望：输出只包含「计划中」的键，且每个都能说出由哪张任务实现（对照本文件 §3 表）
# 注意：$appKeys 是当前 **36** 个键的快照——新增配置项时**必须同步加进这个列表**（否则反查会漏），T4.12 体检会核对 36 这个数。
# 2026-11-14（T3.1 后实测）：死配置 **16** 个（旧口径漏了 getProperty 消费方，曾误报 18 个；T2.7 消费 log-json、T3.1 新增 llm.timeout-sec 均已消费）。

# 6) 阈值 / 端口 / 路径字面量扫描（M4b 口径：8080/9000/5432/6379/200MB/3600）
Select-String -Path .\app\src\main\java\**\*.java -Pattern '8080','9000','5432','6379','209715200','3600'
# 期望：无输出
```

> 第 3 条是"一个不落"的**机器判据**：加了配置却没进 `.env.example`，这个差集就会报出来。
> 第 5 条（D-054）是"配置有没有人用"的**机器判据**：前 4 条只保证"两边对齐"，对齐的**死配置**一条也查不出来。
