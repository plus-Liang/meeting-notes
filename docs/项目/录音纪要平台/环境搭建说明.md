## 2. 三条必须记住的规则

### 规则 1：所有 Docker 镜像都加加速前缀

```powershell
# ❌ 不通
docker pull fedirz/faster-whisper-server:latest-cpu

# ✅ 通
docker pull docker.m.daocloud.io/fedirz/faster-whisper-server:latest-cpu
```

**`docker-compose.yml` 里的 `image:` 同理**，全部加前缀；`.env.example` 的 `ASR_IMAGE` 也必须带前缀。

（另一种做法：往 `C:\Users\<你>\.docker\daemon.json` 加 `"registry-mirrors": ["https://docker.m.daocloud.io"]` 再重启 Docker。
本机 daemon.json 目前**没有** registry-mirrors，所以"加前缀"是当前唯一可靠方式。）

### 规则 2：JDK 用 21，不要用 25

JDK 25 在 Maven 上已经出现告警（`WARNING: A restricted method in java.lang.System has been called … jansi`），
而 Spring Boot 3.3/3.4 官方支持矩阵不覆盖 25。**编译能过 ≠ 运行能过**。

```powershell
# 从华为云拉（已验证可达）
$u='https://mirrors.huaweicloud.com/openjdk/21.0.2/openjdk-21.0.2_windows-x64_bin.zip'
Invoke-WebRequest $u -OutFile E:\tools\jdk21.zip -UseBasicParsing
Expand-Archive E:\tools\jdk21.zip -DestinationPath E:\tools -Force
```

装好后**只在项目会话里**指定，不改全局 `JAVA_HOME`（避免影响你其它 Java 项目）：

```powershell
$env:JAVA_HOME='E:\tools\jdk-21.0.2'
$env:PATH="E:\tools\apache-maven-3.9.9\bin;$env:JAVA_HOME\bin;$env:PATH"
mvn -v      # 期望：Maven 3.9.9 + Java 21.x
```

### 规则 3：本机不能装未签名二进制

`ffmpeg` / `ffprobe` / `sherpa-onnx` / 青笺安装包都被 Windows Smart App Control 拦
（`Application Control policy blocked this file`）。→ **媒体处理全部在容器内**（D-010），宿主机不装。

## 6. ASR 镜像这件事对项目到底有什么影响（影响面分析）

### 6.1 不影响的部分（因为 D-006 的抽象是对的）

ASR 在本项目里是一个**可替换的黑盒服务**，Java 侧只认一个接口：

```http
POST /v1/audio/transcriptions   →  { "text": "…" }
```

所以下面这些**一行业务代码都不用改**，即使 ASR 实现从 FunASR 换成 faster-whisper 再换成云：

- 架构分层、任务模型、状态机、队列、幂等、重试、死信；
- 数据模型（`task` / `task_result` / `glossary` …）、5 个摘要模板、闭环回流；
- 接入面（REST / Webhook / OpenAPI）、配置清单（只改 `ASR_*` 三个变量）；
- 页面、鉴权、配额、备份恢复。

**更强的结论**：**ASR 没定不阻塞业务开发**。可以先用一个"假 ASR"（对任意音频返回固定文本）
把整条链路跑通，等真 ASR 就位后只换 `ASR_BASE_URL`。

### 6.2 真正被卡住的部分（4 条）

| # | 被卡住的 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **T0.1 / T0.2 闸门过不去** | 中 | 拿不到 **RTF**，就无法回答"8.44h 音频要跑 50 分钟还是 3 小时"，而这个数决定产品能否日常用，也决定 README 的容量预期 |
| 2 | **N15（不填 key 也能跑）+ N16（断网可用）** | **高** | 这两条**必须**有本地 ASR。若最终只能上云 ASR，这两条直接不成立 → 要改 spec、改定位、改面试说法 |
| 3 | **交付证据** | 中 | T4.12「真实库 11 个内容全量回归」和 3 分钟录屏都必须真跑一遍，没有可用 ASR 就没有证据 |
| 4 | **进度** | 中 | 自建容器 +0.5–1 天；若你给阿里云加速地址，2 分钟就能解决 |

**风险分级**：架构风险 **0**（接口已经定死）；进度风险 **中**；需求风险 **高**（只有"被迫只能用云"这一种情况才会发生）。

### 6.3 为什么现在推荐"自建极简容器"

1. **本机已有 4.21 GB faster-whisper 模型**（small / medium / large-v3），不用下载；
2. **本机已有 `python:3.12-slim` 镜像**，不用拉任何新镜像；
3. 只依赖 PyPI（可用清华源），**不依赖 Docker Hub / ghcr / daocloud 白名单**；
4. 顺便把 D-006 的"ASR 独立服务"真正落地成我们自己的容器 —— 面试可直接讲"我自己包了一个 OpenAI 兼容 ASR 服务"。

**唯一需要先验证的两件事**（20 分钟）：
- 容器内 `pip install faster-whisper -i https://pypi.tuna.tsinghua.edu.cn/simple` 能否成功；
- 能否加载 `D:\huggingface` 里已有的 small 模型并转写一段真实音频。

两条都通过 → 走自建；第一条失败 → 退回"修一个国内加速源"或"你给阿里云地址"。

## 7. 本机踩到的环境坑（2026-11-13 实测，都不是项目缺陷）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | **宿主注入 `SERVER__PORT=60594`** | 被 Spring Boot 宽松绑定成 `server.port`，与宿主监听端口冲突，应用起不来 | 命令行覆盖：`mvn spring-boot:run "-Dspring-boot.run.arguments=--server.port=18080"`；compose 内不存在此问题 |
| 2 | **本机 curl 走代理** | `curl http://localhost:8080/actuator/health` 被代理拦截/超时 | 加 `--noproxy "*"` |
| 3 | **`docker run -v D:\...:/mig:ro` 偶发容器卡在 `Created`** | 容器创建成功但起不来、日志为空（Windows Docker Desktop 文件共享问题） | 去掉挂载，改用 `docker cp` 把文件送进容器 |
| 4 | **`git push` 偶发 `schannel: failed to receive handshake`** | 国内网络 TLS 握手失败 | 重试 2–3 次；或 `git -c http.sslBackend=openssl push` |
| 5 | **Java 控制台 `stdout.encoding=GBK`** | 用 Bash 捕获中文输出是乱码 | 统一用 **PowerShell** 跑验证命令 |
| 6 | **端口 8000 被别的项目占用** | 容器 `Created` 但起不来 | 宿主端口走 `ASR_PORT`（例如 8001），容器内固定 8000 |
| 7 | **daocloud 只对 `library/` 镜像友好** | `docker.m.daocloud.io/minio/minio` / `ollama/ollama` 返回 `denied`（白名单）；`dockerhub.icu` 能拉但 blob 是坏 HTML（`latest` 解包失败） | 非官方镜像用华为云 `swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/<image>`（实测可拉可跑）；compose 里用 `MINIO_IMAGE` / `OLLAMA_IMAGE` 整体覆盖（D-038） |
| 8 | **temurin 21 的 apt 源是 deb822 格式** | `sed -i /etc/apt/sources.list*` 里的 `*` 还匹配到**目录**，替换静默失效（被 `2>/dev/null` 吞掉），`apt-get update` 走 `archive.ubuntu.com` 被宿主代理 fake-ip 打成 502 | 用 `grep -rlE "archive\.ubuntu\.com\|security\.ubuntu\.com" /etc/apt \| xargs -r sed -i ...` 定位真实文件再换源（Dockerfile 里 `ARG APT_MIRROR` 可覆盖，默认清华源） |
| 9 | **"无 key"验证不许 `mv .env`** | 移走 `.env` 会让 `REGISTRY_PREFIX`/`MINIO_IMAGE` 一起消失 → compose 镜像引用变化、app 容器没重建，`/actuator/health` 的 200 来自**旧容器**（假绿灯） | 用独立探针：`docker run -e LLM_ENABLED= -e LLM_API_KEY= -e LLM_BASE_URL= -e LLM_MODEL= <app-image>`，看容器 health（D-039） |
| 10 | **`LLM_ENABLED=true` + 无 key 启动会崩** | `BeanCreationException: 'openAiApi' ... OpenAI base URL must be set` | 不是缺陷：显式 true = 强制启用（D-036）。测无 key 场景要让 `LLM_ENABLED` 留空 |
| 11 | **连库用 `-U postgres` 会失败** | `FATAL: role "postgres" does not exist` | compose 里是 `POSTGRES_USER=mn`：`psql -U mn -d meetingnotes` |
| 12 | **含中文的 `.ps1` 必须是 UTF-8 带 BOM** | 用 AI 编辑工具改过脚本后，BOM 会被悄悄去掉 → PowerShell 5.1 按 ANSI 读，`'D:\new\docs\项目\…'` 变成乱码路径，脚本报"源文档目录不存在" | 改完立刻补 BOM：`$t=[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8); [IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($true)))` |
| 13 | **宿主机跑 `mvn test` 必须覆盖 `ASR_BASE_URL`** | 不设时 `AsrSmokeTest` 连 `http://asr:8000`（容器内 DNS）→ `ResourceAccessException`，14 用例里 **1 error**（实测）；设成 `http://localhost:8001` 才 14/14 绿 | 跑测试命令里显式带 `$env:ASR_BASE_URL='http://localhost:8001'`（见 `AGENT.md` §4.1 测试命令）；这也是 T3.3 要补 `scripts/test.ps1` 的原因 |
