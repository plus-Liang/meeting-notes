## 0. 为什么做（用户故事）

前提已定（D-239）：**一人一机自部署**，用户既是使用者也是运维。

现在一个陌生人拿到仓库后的真实路径是：

1. 读 README → 跑 `scripts/first-run.ps1`（生成 `.env`、随机 `API_TOKEN`、下载 461 MB 模型、`compose up`）；
2. 浏览器打开 `http://localhost:8080/` → **登录页**；
3. 登录页只有一个「首次使用 · 创建账号」按钮，点了才知道**第一个注册的人自动变成管理员**（`AuthService.claimAdminIfUnclaimed`，条件更新 `WHERE id=1 AND password_hash='!'`）；
4. 之后所有"系统到底配好没有"的问题——ASR 模型加载没加载、MinIO 连没连上、磁盘够不够、之后外部系统用哪个 token——**只能去设置页看或去翻文档**；
5. 出故障时（模型没下完 / ASR 挂了）用户看到的是登录页正常但提交任务失败，或者干脆不知道为什么任务一直 PENDING。

所以向导要解决的**不是**"多一个漂亮页面"，而是三件事：

- **可发现**：新人打开浏览器就知道"这个实例还没初始化，从这里开始"；
- **可自证**：5 项依赖各自给出「通过/不通过 + 一句话怎么修」，而不是让用户猜；
- **只做一次**：初始化完成后这个入口彻底消失（404），不给攻击面，也不让老用户误入。

## 1. 目标 / 非目标

**目标（v1 只做这些）**

1. `/setup` 页面：仅在**尚未认领管理员**时可访问；完成后永久 404。
2. 5 项环境自检（数据库 / Redis / MinIO / ASR 模型 / 磁盘余量），每项给出判据、现状值、失败时的修复指引。
3. **管理员创建改为显式步骤**：向导里填用户名+密码 → 创建并直接进入系统（发一张会话），不再依赖"第一个注册的人自动是管理员"这个隐含规则。
4. 完成页给出：系统地址、`API_TOKEN` 的位置提示（不显示值）、外部接入入口（接入指南链接）、下一步（提交第一条任务）。
5. 全流程中文、无外部依赖、无前端框架（与现有 `static/*.html` 一致）。

**非目标（明确不做，避免膨胀）**

- ❌ 不在浏览器里下载模型（461 MB 走容器内网络，宿主机脚本更可靠，见 §3.4）；
- ❌ 不做安装器/桌面应用（那是另一个量级）；
- ❌ 不做"首次配置向导"的后续编辑（配额、回调地址等仍在设置页）；
- ❌ 不改注册开关语义（`AUTH_REGISTRATION_ENABLED` 仍是"认领后是否允许自助注册"）；
- ❌ 不引入 Spring Security / 模板引擎；
- ❌ 不做多语言。

## 3. 关键设计决策

### 3.1 何时开放、何时 404

**判据只有一个：`AuthService.adminClaimed()`（库里有 role=ADMIN 且密码非占位符的行）。**

- `adminClaimed == false` → `/setup` 与 `/api/v1/setup/*` 可用；
- `adminClaimed == true` → **一律 404**（不是 403）。理由：403 会暴露"这里曾经有个安装入口"，而 404 对普通用户与扫描器都是"没有这个页面"。
- 额外闸门：`/setup` 只接受**本机/私网来源**吗？→ **不做 IP 限制**（反代后 IP 不可信，K-176 同族），改为**凭据闸**：见 §3.3。

### 3.2 管理员创建改为显式（这是本稿最需要你拍板的一条）

现状：第一个 `POST /api/v1/auth/register` 的人**自动成为管理员**（原子条件更新）。这条设计在"自部署"场景下是便利，在"暴露到公网但还没初始化"场景下是**接管风险**——谁先注册谁是管理员。

向导版做法（二选一，等你定）：

- **选项 甲（保守，推荐）**：保留现有自动认领逻辑不变，向导只是**引导**用户去创建（内部仍走 `register`）。风险与现状相同，但至少用户知道自己在"认领管理员"。
- **选项 乙（更严）**：向导页生成一个**一次性安装码**（`SETUP_CODE`，写在 `.env`，`first-run` 打印到终端），创建管理员时必须同时提交该码；未带码的 `register` 在 `adminClaimed=false` 时直接 403「请使用安装向导初始化」。收益：即使实例暴露在公网，陌生人没有终端里的码也抢不走管理员。

我更倾向 **乙**：成本约 30 行（比较码 + 常量时间比较 + 一次性失效），把"谁先注册谁是管理员"这个隐患一次解决；且 `.env` 已经由 `first-run` 生成，多一个随机值不难。

### 3.3 免鉴权面怎么控

新增的免鉴权路径只有三条，全部挂在 `ApiTokenFilter` 的精确豁免里（与 `GET /api/v1/auth/status` 同款写法，不做前缀通配）：

| 路径 | 方法 | 作用 | 约束 |
|---|---|---|---|
| `/api/v1/setup/status` | GET | 返回 `{needsSetup, checks[]}` | 仅 `adminClaimed==false` 时 200，否则 404；**不含**任何凭据/内网地址（注意 `AsrHealthIndicator` 现在会把 `url` 放进 details，向导接口自己取数，不复用那个 details） |
| `/api/v1/setup/admin` | POST | 创建管理员（用户名+密码[+安装码]） | 走 `login`/`register` 同一套 `RateLimitInterceptor`（建议单 IP 5/分钟）；成功后立刻 `adminClaimed=true` ⇒ 后续调用 404 |
| `/api/v1/setup/model` | GET | 模型状态（`{model, ready}`） | 透传 ASR `/health` 的 `model`/`ready`；失败返回 `{ready:false, reason:"..."}`，不抛 500 |

`/setup.html` 本身是静态资源，静态页**不含数据**，数据全由上面三个接口给。

### 3.4 模型下载进度：向导只**显示**，不发起

- ASR 容器 `/health` 已返回 `{"status":"ok","model":"small","ready":true}`（`infra/asr/server.py:58-60`）⇒ 向导据此判断"模型已加载"。
- 但"模型正在下载"这件事发生在**宿主机**（`scripts/download-model.ps1`，容器内 HuggingFace 下载 + 进度条），浏览器无法感知，也不应该由浏览器触发 461 MB 传输。
- 所以：模型项判据 = 「ASR `/health` 可达 且 `ready==true`」。不通过时给出**两条修复指引**（按平台）：
  - Windows：`scripts\download-model.ps1`；Linux/macOS：`scripts/first-run.sh`（内含同一段模型下载，见其第 41–53 行）
  - 直接看容器日志：`docker logs -f meeting-notes-asr-1`（失败原因写得很清楚：`模型未找到或加载失败（ASR_MODEL_NAME=…，模型目录=/models）`）
- **可选增强（不进 v1）**：让下载脚本往 models 目录下写一个进度文件（如 .download-progress.json），向导读该文件显示百分比。等有人真的抱怨"不知道下载到哪了"再做。

### 3.5 自检失败 = 提示，不阻断（除数据库）

用户可能"先建管理员、后修 ASR"。所以：

- **硬阻断**（不通过则不能进下一步）：无。数据库挂了应用根本起不来，向导页也打不开，无需在页面上重复。
- **软提示**（显示红/黄，但可以继续）：Redis / MinIO / ASR / 磁盘。
- 完成页会保留一份"上次自检结果"，并给"重新检测"按钮（同一个 `GET /status`）。

### 3.6 幂等与重入

- 向导可重复进入（刷新、关标签再开）——所有状态都从服务端现算，无会话。
- 创建管理员是**一次性**的：靠 `adminClaimed` 反转 + 原子 UPDATE（复用 `claimAdminIfUnclaimed` 的条件更新，0 行即"已被认领"→ 409 `SETUP_ALREADY_DONE`）。
- 不做"向导进行到第 3 步"的服务端状态：步骤只在前端，刷新回到第 1 步即可（安装只要 2 分钟）。

## 4. 页面与流程（5 屏）

```
/login.html ──(adminClaimed=false 时多一个链接)→ /setup.html
                                                    │
   ① 欢迎 + 环境自检（自动跑 GET /api/v1/setup/status）
        · 5 行状态：数据库 / Redis / MinIO / ASR 模型 / 磁盘
        · 每行：图标 + 名称 + 现状（如「Redis 已连接（PING 3 ms）」）+ 失败时的修复指引
        · 「重新检测」按钮
   ② 创建管理员
        · 用户名（3–32，字母数字下划线）/ 密码（≥8）/ 确认密码
        · [乙方案] 安装码（默认折叠，提示"在终端里 first-run 输出的 SETUP_CODE"）
        · 提交 → POST /api/v1/setup/admin → 成功即写入会话 → 跳到 ③
   ③ 完成页
        · 「系统已就绪」+ 当前地址
        · 三条下一步：提交第一条任务 / 看接入指南（外部系统用 API_TOKEN，值在 .env）/ 进设置页
        · 提示：此页面之后将不可访问（404）
```

`/login.html` 的改动：当 `auth/status` 返回 `adminClaimed=false` 时，除了现有的「首次使用 · 创建账号」，再加一行 **「首次部署？进入安装向导 →」**（纯链接，不抢主流程）。

## 5. 五项自检的判据（写码时必须逐字对齐）

| 项 | 判据（服务端） | 通过文案 | 失败文案（含修复指引） |
|---|---|---|---|
| 数据库 | `SELECT 1` 成功（3s 超时） | 数据库已连接 | 数据库不可用：`docker logs meeting-notes-postgres-1` |
| Redis | `PING` 成功（3s 超时，复用 T4.90 的连接超时键） | Redis 已连接（`PING` N ms） | Redis 不可用：`docker logs meeting-notes-redis-1`；队列会暂停投递 |
| MinIO | `headBucket(audio)` 成功（5s 超时） | 对象存储已连接（桶 `audio`） | 对象存储不可用：检查 `.env` 的 `S3_ENDPOINT/S3_ACCESS_KEY/S3_SECRET_KEY` |
| ASR 模型 | `GET {ASR_BASE_URL}/health` 5s 内 200 且 `ready==true`，返回 `model` 名 | 语音模型已加载：`small` | 模型未加载：Windows 先跑 `scripts\download-model.ps1`，Linux/macOS 跑 `scripts/first-run.sh`，再 `docker logs -f meeting-notes-asr-1` 看原因 |
| 磁盘余量 | 复用 `StorageGuard.usableBytes()`，与 `.env` 的 `STORAGE_MIN_FREE_MB` 比较 | 磁盘剩余 N GB（下限 M MB） | 磁盘空间不足：剩余 X，低于下限 Y——清理后再试（可点设置页「清理孤儿对象」） |

> 注意：**磁盘项复用 T4.92 的 `StorageGuard`**（403/503 语义只用于上传，向导这里只读一次、不触发任何删除）。

## 6. 接口契约草案（逐字，写码时不得改名）

```
GET /api/v1/setup/status        (免鉴权；adminClaimed=true → 404)
200 {
  "needs_setup": true,
  "checks": [
    {"key": "postgres", "label": "数据库",   "ok": true,  "detail": "已连接"},
    {"key": "redis",    "label": "Redis",   "ok": true,  "detail": "PING 3 ms"},
    {"key": "minio",    "label": "对象存储", "ok": true,  "detail": "桶 audio"},
    {"key": "asr",      "label": "语音模型", "ok": true,  "detail": "small"},
    {"key": "disk",     "label": "磁盘余量", "ok": true,  "detail": "剩余 898.5 GB（下限 2048 MB）"}
  ]
}

POST /api/v1/setup/admin        (免鉴权；adminClaimed=true → 404)
body {"username":"admin","password":"...","setup_code":"..."}   // setup_code 仅乙方案
200  {"user_id":1,"username":"admin","role":"ADMIN","token":"<会话令牌>"}
400  {"code":"INVALID_PARAM","message":"..."}
403  {"code":"SETUP_CODE_INVALID","message":"安装码不正确（在终端里 first-run 输出的 SETUP_CODE）"}
409  {"code":"SETUP_ALREADY_DONE","message":"实例已完成初始化"}

GET /api/v1/setup/model         (免鉴权；adminClaimed=true → 404)
200  {"model":"small","ready":true}
200  {"model":"small","ready":false,"reason":"ASR /health 不可达"}
```

前端一律用现有 `static/auth.js` 的 `apiFetch`（会自动带会话令牌，但向导三条接口都不需要令牌）。

## 8. 验收要点草案（写码后我会这么测）

- A1：全新库（空 volume）→ `GET /setup/status` 200 且 5 项齐全；`/setup.html` 可打开。
- A2：5 项逐项**造故障**（停 Redis、停 MinIO、停 ASR、改小 `STORAGE_MIN_FREE_MB` 阈值制造磁盘项红）→ 各自 `ok=false` + 文案逐字 + **其余项仍返回**。
- A3：创建管理员 → 200 + 令牌可用（`/api/v1/tasks` 200）；再调 `/setup/status` → **404**；再 POST 一次 → **404**（不是 409；404 优先，避免暴露）。
- A4：乙方案安装码错误 → 403 `SETUP_CODE_INVALID`；正确 → 200；码用后即失效。
- A5：已有管理员的实例（如当前主栈）→ `/setup.html` 404、三接口全 404。
- A6：限流：6 次 POST 内出现 429。
- A7：真浏览器：陌生人路径（干净 profile）从 `/` → 登录页链接 → 向导 → 建管理员 → 进首页，全程 ≤ 3 分钟、无 `window.confirm`、无 JS 报错。
- A8：`-UnitOnly` 全绿、门禁 0/0、docguard 0/0；主栈部署后 `/setup` 404（已初始化）、`/login.html` 不再出现向导链接。

## 9. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 新增免鉴权面被滥用 | 仅 3 条精确路径；`adminClaimed=true` 立即 404；POST 限流；乙方案加安装码 |

| 回滚 | 纯新增 + 3 行豁免 + 1 处限流；回滚 = revert 一个 commit，无迁移、无数据影响 |
