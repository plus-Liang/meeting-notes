### D-001 交付形态定为 Web 应用
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：唯一交付形态为 B/S 架构 Web 应用（Spring Boot API + 3 个页面 + Swagger UI + `docker compose up`）。
- **依据**：目标是 Java 后端实习，需要"能点开、能调接口"的后端证据；Web 最标准。
- **已排除项**：微信小程序（需已备案域名 + HTTPS + 审核周期，与 4 周时间盒冲突；音频类目易卡审核）；桌面客户端（Electron/Tauri 把重心拉离后端，后端会退化成"本地服务"）。

### D-002 形态定为 self-hosted 开源，不做 SaaS
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：以「个人自用为第一目标 + 可开源供他人自部署」交付；不做公网多用户托管。
- **依据**：身份从"服务提供者"变为"工具作者"，版权责任随部署转移；无服务器成本、无运维负担。
- **已排除项**：SaaS（版权风险 + 运维成本 + 被攻击面）；纯个人自用不开源（放弃可展示性与二次使用价值）。

### D-003 不与商业产品比功能，只服务三类用户
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：定位为「中文 + 可自托管 + 数据不出本机 + Java 生态」的交集；只服务 A 本地文件囤积者 / B 数据不能出门者 / C 要接进自己系统者。
- **依据**：功能竞争必输（飞书妙记、通义听悟、讯飞听见更成熟）；self-hosted 品类的用户从不被"功能"说服，而被"数据控制权"说服（参照 Immich/Jellyfin/Nextcloud）。
- **已排除项**：做"更好的飞书"（必输）；以 star 数为目标（同类太多，0 star 是常态）；"为了学习"当理由（在面试里等于承认项目无价值）。

### D-004 默认路径必须零成本可跑
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：不填任何 API key，P1 用户故事必须全部可走通（本地 ASR + 模板/本地 LLM 摘要兜底）。
- **依据**：开源项目"clone 下来第一步就要充钱"是 0 star 的直接原因。
- **已排除项**：强制 BYO-key（抬高门槛）；只有云通道（隐私与成本双输）。

### D-005 不自研 ASR / LLM 模型
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：只做编排层；模型一律外部调用。代码库不得出现权重文件与训练脚本。
- **依据**：4 周时间盒内自研不可能；本项目价值在任务编排、可靠性、成本控制。
- **已排除项**：训练/微调模型（跑不动、无面试价值）；自己实现推理（重复造轮子）。

### D-006 ASR 独立成服务，走 OpenAI 兼容协议
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：ASR 以独立容器提供服务，暴露 OpenAI 兼容的 `/v1/audio/transcriptions`。
- **依据**：FunASR 官方即提供 OpenAI 兼容服务；接口稳定后，实现可整体替换而 Java 侧零改动。
- **已排除项**：Java 内嵌 JNI 调模型（依赖地狱）；私有协议（换供应商要改代码）。

### D-007 LLM 全部走 OpenAI 兼容协议（可切国内模型）
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：摘要/待办统一经 OpenAI 兼容端点调用，`base-url + model + key` 三者可配；默认支持智谱 GLM、DeepSeek、Kimi、通义/百炼、本地 Ollama。
- **依据**：这些平台均提供 OpenAI 兼容模式，一套适配器覆盖全部。
- **已排除项**：为每家写专属 SDK（维护成本爆炸）；绑死单一供应商（用户无法自选）。
- **备注**：各家的确切 base-url 与模型名在编码当天必须 curl 实测，未实测不写默认值。

### D-008 默认中文 ASR 选 FunASR（不是 whisper 系）
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：默认容器为 FunASR；whisper.cpp / faster-whisper 作为备选实现。
- **依据**：中文、方言、标点、VAD、说话人 pipeline 是 FunASR 的强项；本场景输入以中文为主。
- **已排除项**：whisper small/medium 做默认（中文标点与专有名词表现较弱，本人本机实测过）。

### D-009 任务用「PG 任务表 + Redis 分发」，不用纯消息队列
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：任务状态落 PostgreSQL，Redis 只做分发/限流/缓存。
- **依据**：任务需要可查、可重试、可重投、可统计；纯 MQ 里的消息不可观测，无法满足幂等与死信的可视化要求。
- **已排除项**：Kafka（规模不匹配）；RabbitMQ 单独承担状态（查询困难）；纯内存队列（重启即丢）。

### D-010 媒体处理全部在容器内完成
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：ffmpeg 抽音轨、ASR 解码都在容器内；宿主机不安装媒体工具。
- **依据**：本机实测 Windows Smart App Control 会拦截未签名二进制（ffmpeg/ffprobe/sherpa-onnx 报 `Application Control policy blocked this file`）。
- **已排除项**：宿主机直装 ffmpeg（本机被策略拦截，且换机器不可复现）；用 Python 库绕开（同样受策略影响）。

### D-011 对象存储用 MinIO（S3 协议）
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：原始文件与产物存 MinIO，走 S3 兼容 API。
- **依据**：本地可跑、零成本、后续可无缝换成真实 S3/OSS；不把文件放容器本地目录（重建即丢）。
- **已排除项**：直接落本地磁盘（不可扩展、易丢）；直接用云 OSS（破坏"零成本可跑"）。

### D-012 许可证选 MIT
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：MIT。
- **依据**：采用门槛最低、最利于被使用与展示；求职场景不需要防止商用。

### D-013 不做实时流 / 会议机器人 / DRM / 网盘 / 页面链接

### D-018 不把 GitHub star 当 KPI
- **日期**：2026-11-13｜**决策人**：本人

### D-019 对外接入面只做 「REST API + Webhook + OpenAPI」
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：外部系统接入本项目的路径只开放三个面：①REST API（Bearer Token）②Webhook 终态回调（HMAC 签名、至少一次投递、去重键）③OpenAPI 规范 `/v3/api-docs`。inbox 目录与导出为 P2，MCP 为 P3。细节见 `接入指南.md`。
- **依据**：C 类用户（要接进自己系统的人）是定位的一部分，必须有真实接入面；但给每家客户端写插件是无底洞（违反 D-015）。API + Webhook 是最小稳定面，n8n/Zapier/脚本/群机器人/AI agent 全部能长在它上面。
- **已排除项**：为飞书/Obsidian/VSCode 各写一个插件（成本高、4 周做不完）；官方多语言 SDK（用 OpenAPI 自动生成即可）；数据库直连或只读账号（强耦合表结构，升级即坏）；OAuth2/多租户（单用户自托管，Token 足够，见 D-002）。

### D-020 AI 能力做成三档降级，所以"零成本可跑"成立
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：摘要/待办按 ①云 API（有 key）→ ②本地 Ollama（启用且可用）→ ③抽取式兜底（关键句 + 规则待办 + 模板）顺序降级；结果记录 `ai_tier`（CLOUD/LOCAL/EXTRACTIVE）；三档必须输出相同字段结构。
- **依据**：**"接入 AI"不等于"必须买 API key"**。ASR 本身完全本地免费；LLM 这一档有本地模型与抽取式两条免费路径。开源项目"clone 下来第一步要充钱"会直接废掉采用价值（D-004）。
- **已排除项**：只支持云 API（抬高门槛、破坏离线场景）；只做抽取式（质量不够，称不上 AI 项目）；强制跑 Ollama（8GB 内存门槛，低配机器直接不能启动）。
- **诚实标注**：抽取式**不是** AI 摘要，是"关键句提取 + 规则抽取"，质量明显更低；README 必须写清三档差异，不许把 ③ 当 ① 宣传。

### D-021 配置全部外置，"一个不落"，并带机器判据
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：路径、端口、key、并发数、模型名、配额、webhook、inbox、离线开关、日志级别——全部有环境变量入口；`.env.example` 是唯一事实来源；每个任务的 DoD 必须跑 `配置清单.md` §2 的三条自检命令。
- **依据**：这是"可自托管/可换环境/可换模型"的物理前提；也是 D-004（零成本可跑）、D-007（换供应商）、D-001（换工作区）能成立的基础。硬编码一处，别人就起不来。
- **已排除项**：把配置写进 `application.properties` 常态值（改配置要重新打包）；只用 docker-compose 传环境变量而应用侧仍写死默认值（两套来源必然漂移）；"只把 key 外置，其它写死"（这正是最常见的半成品）。

### D-023 备份与恢复只做本地，且不备份密钥
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：`backup.ps1` 产出 `./backups/<时间戳>/{pg.dump, objects/, MANIFEST.md}`；每日自动、保留 7 份；`restore.ps1 -From ... -Force` 恢复前先把现有卷改名留存；**`.env` 不进备份**（只放 `.env.example` 副本）。
- **依据**：工作流与 PRD 都要求"数据本地保存与备份"；本项目卖点是"数据不出门"，丢数据等于毁掉信任（US-11 / N18–N20）。
- **已排除项**：云备份（违背"数据不出门"）；跨机器同步（规模不匹配，D-015）；备份加密（P2 再说）；把恢复做成网页按钮（误点即毁库，只给命令行 + `-Force`）。

### D-024 页面状态刷新用 3 秒轮询，不用 WebSocket/SSE
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：任务列表每 3 秒轮询一次；不引入 SSE/WebSocket。

### D-025 新增用户与输入来源走「零成本覆盖」原则，不进 v1 时间盒
- **日期**：2026-11-13｜**决策人**：本人
- **结论**：新增场景（学生/播客/访谈/远程会议）一律通过**摘要模板**覆盖，不新增管线；
  新增输入入口（RSS/MCP/OCR/INBOX/RECORD）全部进 P2/P3 backlog，**不进 v1 必做**。
- **依据**：调研发现"新增用户 ≈ 新增一个模板"（见 `目标用户与输入来源-调研.md` §1）；
  而每条新输入入口都是 2–6h 的独立工作量，时间盒已满（62h）。
- **已排除项**：为每个场景写一套独立流程（代码爆炸）；为凑场景数量加输入入口（违反 D-015）。

### D-027 明确不做「平台页面链接抽取」，给替代路径

### D-027R 修订 D-027：链接处理改为「L1 元信息确认 + L2 直链探测 + BYOF 接口」
- **日期**：2026-11-13（用户提出"粘链接 + 用户确认是不是这个视频"后修订，supersedes D-027 的"一律不做"）｜**决策人**：本人
- **结论**：链接不再"一棍子打死"，改为三级阶梯（详见 `链接处理方案.md`）：
  - **L1**：粘链接 → 读取公开元信息（`og:title`/`og:image`/公开时长）→ 显示"是这个视频吗？"确认卡片；
  - **L2**：普通 GET 跟随公开重定向，若最终 `Content-Type` 是 `media/*` → 当直链直接进管线（**不做逆向、不伪造签名、不带用户 cookie**）；
  - **L2 失败** → 降级提示"请导出后上传"（手机浏览器上传，D-029）；
  - **BYOF**：定义 `MediaFetcher` 接口 + `FETCHER_CMD` 配置，仓库**不含**任何平台解析器；想抓的人自己装 yt-dlp。
- **依据**：L1/L2 只读公开信息与公开重定向，合规成本低、零平台适配器、失败自动降级不会坏；能实现用户"确认是这个视频"的核心诉求。
- **已排除项**：**内置全平台解析器（L3）**——①绕过技术措施，且 D-003R 把目标改成"给别人用"后，从"个人灰色"升级为"分发合规风险"；②每平台签名数月一改，是维护黑洞，直接杀死时间盒；③需要存用户平台 cookie，与"数据不出门"的信任叙事冲突；④对面试价值≈0。
- **增量成本**：+2 天（16h）→ 总工期 67h → **83h**，需重新排期（见 `tasks.md`）。
