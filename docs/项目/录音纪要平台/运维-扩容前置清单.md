## 3. 扩容五步（按顺序）

1. **入口与端口**：去掉 app 宿主端口映射（override `ports: !reset []`），前置反代统一入口。
   为什么：固定映射起不了第二副本（§5）。怎么验：`--scale app=2` 全 healthy 且反代轮询命中两副本。
2. **幂等认领**：复用现有条件 UPDATE（已具备）。为什么：防双处理。怎么验：20 任务每条「开始转写」恰 1 次（tasks-once.txt）。
3. **心跳/可见性/恢复 + webhook 租约**：复用 TaskHeartbeat/Sweeper/StartupRecovery（已具备）；
   webhook 扫描加租约（`SELECT .. FOR UPDATE SKIP LOCKED` 或条件 UPDATE 认领、影响行数=1 才投）。
   为什么：副本崩溃不丢任务、到期投递不重复。怎么验：kill 一副本残留被回收；dup 探针每 delivery 恰 1 次。
4. **限流与配额**：限流计数改共享（Redis）或上移反代层；配额已落 PG 无需改。
   为什么：JVM 计数被副本数放大（§5）。怎么验：两副本同 key 的 429 出现点与单副本一致。
5. **多副本验收剧本**：按 §4 全量跑一遍，含失败注入与重复投递断言。

## 4. 多副本验收剧本

隔离栈 `-p mn-t488w`；宿主端口一律 `$env:`（K-194），任何 docker 命令不漏 `-p`。配方见 scale-2replica.md。

```
$env:APP_PORT="18288"; $env:ASR_PORT="18298"; $env:MINIO_PORT="19188"; $env:MINIO_CONSOLE_PORT="19189"; $env:NGINX_PORT="18288"
docker compose -p mn-t488w -f docker-compose.yml -f override-nginx.yml up -d --scale app=2
# 断言1：app-1/app-2 均 healthy；nginx 轮询两副本（resolver 127.0.0.11 valid=1s）
# 断言2：20 条 PASTE → 20/20 DONE；合并两副本日志「开始转写」per taskId 恰 1 次
# 断言3：插 due webhook_delivery 行 + 探针 → 每 delivery_id 命中恰 1 次（加租约后）
# 断言4：同 key 错密码登录，两副本 429 出现点 == 单副本（限流共享后）
# 断言5：kill 一副本 → 残留回执被另一副本回收、任务不丢
docker compose -p mn-t488w -f docker-compose.yml -f override-nginx.yml down -v   # 残留必须 0
```

## 5. 已知阻碍与本轮实验结果

- **`--scale app=2` 报错**：复现。原文见 scale-fail.txt：`Bind for 0.0.0.0:18288 failed: port is already allocated`（app-2）。
- **两副本 20 任务**：复现（已具备）。20/20 DONE、每条「开始转写」恰 1 次（tasks-once.txt）。
- **webhook 重复投递**：重试路径**复现**（dup-webhook.txt：同一 delivery 被 app-1/app-2 各投 2 次、attempts=4）；
  成功首投**未复现**——`attempt()` :143-144 先原子自增+置 next_retry=NULL，SELECT→attempt 的 dup 窗口仅毫秒级。
- **限流倍数**：复现。单副本第 11 次 429（桶=10）；两副本放过 ~17 次才稳定 429（rate-limit-x2.txt）。
- **inbox 多副本同扫**：未验证（默认 enabled=false；验证方法=开启后两副本同放文件断言入队一次）。
- **ASR 承载副本数上限**：未验证（asr 单容器，未压测；验证方法=梯度副本+压测看 ASR 排队/超时）。
