## 1. 简历条目（草稿）

> **MeetingNotes｜自托管录音/网课转纪要平台**（个人项目，开源）
> Java 17 · Spring Boot 3 · Spring AI · PostgreSQL · Redis · MinIO · Docker Compose
>
> - 独立设计并实现「上传/直链/字幕/浏览器录制 → 转写 → 结构化摘要与待办 → 术语回流」的端到端流水线，
>   支持 OpenAI 兼容协议对接 FunASR 与多家 LLM（智谱/DeepSeek/Kimi/通义），**不填 API key 也可本地零成本运行**。
> - 任务系统基于「PG 任务表 + Redis 分发」实现幂等、重试退避、死信与崩溃恢复，
>   单文件处理时延从人工 40 分钟降至 **【TBD 实测】分钟**，ASR 实测 RTF **【TBD 实测】**。
> - 实现术语表回流机制：用户修正结果自动沉淀并在后续任务生效，专有名词识别准确率 **【TBD 实测】**。
> - 全链路 `docker compose up` 一键启动，含健康检查、结构化日志（taskId 贯穿）、配额限流与 SSRF 防护。

> 简历里**只写实测值**。测不到就把定量描述改成定性描述，绝不编数字。

## 2. 三分钟讲法（背下来，按这个顺序说）

**① 一句话（20 秒）**
> 我做了个自托管的录音转纪要工具。定位不是替代飞书妙记，而是解决另一类场景：
> 手里有大量本地录音文件、要批量处理、且部分内容不适合上传第三方云。

**② 为什么做（30 秒——必须说真实动机）**
> 我自己有几十个网课和会议的 mp4/mp3 堆着，整理一个要 40 分钟：先跑 ASR，再人工读全文写纪要。
> 试过商业产品，但它们是为"一次会议"设计的——我要的是批量提交 10 个文件、失败能重试、断了能续。

**③ 架构怎么来的（40 秒——这段最容易被追问，务必诚实）**
> 先说结论：**没有能直接抄的 Java 全栈同类项目**，我搜过，相关仓库最高 9 星还是 demo。
> 所以我的架构是组装出来的，每一层都有出处：转写层用 FunASR 官方的 OpenAI 兼容服务——
> 它是 2 万星的工业级中文 ASR；Java 侧全部走 Spring AI 官方 API；产品功能分层参考了一个
> 3 万星的开源本地会议助手。**我做的是编排和业务：任务状态机、幂等重试、降级、配额、结构化抽取。**

**④ 最难的地方（40 秒）**
> 长任务系统。转写一个 30 分钟音频要几分钟，中间可能失败、可能重启。
> 所以我把任务状态落 PG 做成状态机，Redis 只做分发，实现幂等（content_hash 唯一）、
> 重试退避、死信可重投、启动时回收僵尸任务。这块才是我觉得最像生产代码的部分。

**⑤ 闭环（30 秒——差异化）**
> 大多数同类项目是"转完给你段文字"就结束了，那是流水线。
> 我加了回流：用户改错词之后进术语表，下次转写就带上；说话人标成"老板"会记成档案。
> 这才叫闭环——系统会因为你用得越多而变准。

**⑥ 边界（20 秒——这段极加分）**
> 我知道自己的边界：稳定性肯定不如商业产品，功能也少得多。
> 所以 README 里我专门写了一节"你不该用这个项目的场景"——只要你偶尔转一次会议、要实时字幕，
> 就直接用飞书妙记，别用我的。

## 3. 高频追问与答法（12 个）

> **"你遇到过什么问题、怎么解决、效果怎么样"的完整题库见 `踩坑与复盘-面试用.md`**（K-01~K-30：现象/定位/根因/修复/量化效果/30 秒口述；
> **G 节专讲"怎么管 AI 写代码"**——AI 写码方的 7 个坑 + 7 道闸门，问"用过 AI 写代码怎么保证质量"直接答它），
> 本表只放"为什么这么设计"类的追问。数字一律引自 `docs/协作/review/` 的独立验收报告。

| # | 追问 | 答法要点 |
|---|---|---|
| 1 | **为什么不用飞书妙记？** | 三句：①大部分场景应该用它，我也推荐；②但它为"一次会议"设计，我有几十个本地文件要批量、要断点、要接自己系统；③部分内容不适合上传第三方云。定位是取舍不同，不是替代。 |
| 2 | **为什么不找个开源项目改？** | 明确说：没有可用的 Java 全栈同类（检索数据：`meeting minutes transcription java` 0 个仓库，spring boot 相关最高 9 星）。同类是 Python/Rust/桌面的。我用权威组件组装，不 fork 冒充自研。 |
| 3 | **为什么不自研模型？** | 4 周时间盒内不可能；项目价值在编排与可靠性；自研模型既跑不动也无面试价值。 |
| 4 | **为什么用 PG 存任务而不是只用 MQ？** | 任务要可查、可重试、可重投、可统计；纯 MQ 的消息不可观测，做不到死信可视化与幂等。 |
| 5 | **怎么保证任务不丢？** | 幂等键 content_hash 唯一约束 + 状态机 + 重试退避 + 死信 + 启动回收 RUNNING 僵尸任务。每一项有对应测试/演示。 |
| 6 | **音频很长怎么办？** | VAD 分段 + 分片处理 + 超时与断点；单任务上限 **60 分钟**（D-028，真实数据 45% 超 30 分钟）是产品约束，不是技术缺陷。 |
| 7 | **换一家模型麻烦吗？** | 不麻烦：全部走 OpenAI 兼容协议，改 base-url + model + key 三个环境变量即可；已支持智谱/DeepSeek/Kimi/通义/本地 Ollama。 |
| 8 | **没 API key 怎么跑？** | 本地 ASR + 模板/本地 LLM 兜底，P1 功能全部可走通。这是开源项目能不能被用的生死线。 |
| 9 | **安全怎么考虑？** | 上传按 magic number 校验；直链 SSRF 防护（拒私网/元数据地址）；配额限流；密钥全走 env 不入库不入镜像。 |
| 10 | **为什么媒体处理在容器里？** | 本机 Windows Smart App Control 会拦未签名二进制（ffmpeg/sherpa-onnx 实测被拦），所以全部放容器；顺带解决换环境可复现。**这是真踩过的坑。** |
| 11 | **这个项目有什么不足？** | 主动说三条：①单机部署，没有高可用；②ASR 质量受模型限制，专业术语靠回流补；③没有多人协作与权限体系。**能主动说不足比硬吹可信。** |
| 12 | **有真实用户吗？** | 【实测】第一个用户是我自己，连续使用 __ 周、累计处理 __ 个文件、__ 小时音频。外部用户 __ 个（能跑通即算）。 |
| 13 | **别人怎么把你这套接进自己系统？** | 只开放三个接入面：REST API（Bearer Token）、Webhook 终态回调（HMAC-SHA256 验签、至少一次投递、delivery_id 去重）、OpenAPI `/v3/api-docs`。其余（inbox 目录、导出、MCP）都是派生。我证明了它能被接入：三条 curl 走完全流程 + 一个 20 行接收端能收 Webhook 并验签通过。**没给每家写插件，因为那是无底洞。** |
| 15 | **怎么覆盖学生/播客/访谈这么多场景？不写四套流程吗？** | 不写。我发现这批场景的**输入与处理是同一套**，只有"输出长什么样"不同（会议要决议待办、课程要知识点考点、访谈要金句、播客要章节 Show notes）。所以我做的是**一份管线 + 四套提示词模板**，提交时选或按文件名自动推荐。扩展到新场景的成本是写一个提示词，不是写一套流程——这是架构取舍，不是功能堆砌。 |
| 16 | **这项目给谁用？你自己用吗？** | 目标是**给别人用**的开源自托管工具（D-003R）。我自己是第一个用户，手里的几十个网课/会议录音是真需求。KPI 我定的是外部真实跑起来的人数，不是 star——收藏不等于部署。 |
