## 2. 别踩的坑（最高频）

1. **改 commit ≠ 改 build/up ≠ 安全**（K-68/K-77）：改了 `static/` 必须重建 app 并比对二进制字节。
2. **Lead 不改产品代码**（K-63）：写码方单 commit 不 push；文档只改 `D:\new\docs\...` 权威版再 sync；**写码方在代码仓改过的 docs 必须先回灌**（K-195/K-203）。
3. **行号一律用 python `splitlines()`**（K-182），`Select-String`/`Get-Content` 在无 BOM 中文文件上会错。
4. **卡面白名单要含 `app/src/test/java/**`**（K-192）；worktree 要预先准备 `.env`、`ASR_MODEL_HOST_DIR`、compose `environment:`（K-210）。
5. **负向对照不能被同源**（K-204）；**验收装置不能裁掉失败原因**（K-205）：判据落在 401/异常体，不是 unhealthy 状态位。
6. **契约测试要 Lead 亲手两变异**（改值 + 删键，K-206）；**时间类验收标准先问"谁能让它变"**（K-207）。
7. **按钮类交付必须真点一遍**（K-214）：GET 打 POST 端点这种错误，单测与截图都看不见。
8. **卡面写行数预算就必须同时给可执行判据**（K-213），否则只能靠自觉。
9. **SDK varargs builder 是整表设置**（K-212）：`contents(S3Object...)` 循环调用只留最后一个。
10. **"单事务"不能只靠 mock**（K-197）；新不变量对历史行不成立要写"对 V<N> 之后创建的任务成立"（K-198）。
11. **`git status` 的 `.M` 幻影**：index 与 HEAD blob hash 相同时就是噪声（K-211）。
12. **PowerShell / 脚本陷阱**：无 heredoc（K-196）；脚本名别遮标准库；命令行别直接写 JSON；`docker logs > f` 是 UTF-16（K-193）；提交信息别用 `Out-File -Encoding utf8`（K-179，带 BOM）；别把脚本输出接 `| Tee-Object | Select-Object`（K-199 会改退出码）；改 `.ps1` 要补 BOM（K-102）；python 写文档用 raw 字符串（K-208）。
13. **compose `ports:` 是追加**、shell 变量不进容器（K-194）；`deploy-main.ps1` 只重建 app（K-155）。
14. **前端验收**：系统 Edge + `playwright-core`（`channel:'msedge'`），真实指针点击（K-117）；前端卡验收后必须在 8080 复验（K-136/D-210）。
15. **限流跑在 controller 之前**：验 404/403 语义前先复位窗口，否则被 429 抢先（K-218）。
